## Key Technical Decisions

### S3 Vectors has no local emulator
- **Finding**: LocalStack does NOT support `s3vectors` (as of June 2026). There is no moto mock, no Docker emulator.
- **Decision**: Use a `FakeVectorStore` dataclass with in-memory dict + naive cosine similarity for unit/component tests. Production code should accept a `VectorStoreProtocol` so the fake satisfies it.
- **Impact**: All sibling issues touching S3 Vectors (#1354) must use this adapter pattern. Live tests must be gated by `@pytest.mark.live`.

### OSV-Scanner deterministic CI strategy
- **Finding**: OSV-Scanner supports `--offline` mode with `--download-offline-databases`. Once the DB is cached, scans are deterministic against a fixture lockfile.
- **Decision**: For unit tests, use a `FakeOSVScanner` with pre-seeded known vulns. For component/integration, pin the offline DB and scan `tests/fixtures/vulnerable-requirements.txt`.
- **Planted CVE**: `requests==2.25.0` → CVE-2023-32681 (SSRF via redirect). This is a stable, well-known CVE that will remain in the OSV database.

### Trivy deterministic CI strategy
- **Finding**: `trivy sbom ./local-file.cdx.json` works with local CycloneDX JSON. Use `--skip-db-update` with a cached DB for reproducibility. CycloneDX XML is NOT supported — JSON only.
- **Caveat**: Trivy warns that SBOMs generated by tools other than Trivy may produce inaccurate results (relies on custom properties).

### Permission testing is highest priority
- **Rationale**: A miss in the ACL filter = cross-tenant data exposure. Made this the first and most thorough test file (16 tests covering 6 scenarios).
- **Design**: `FakeACLStore` with `filter_results(principal_id, results)` method. Key property: `filter_results(None, anything) == []` — fail-closed.

## What Worked Well

1. **Dual-mode test architecture** — The existing `conftest.py` pattern (MockKubeClient vs LiveKubeClient) extends cleanly. New fixtures follow the same pattern.
2. **pytest marker auto-skip** — `pytest_collection_modifyitems` handles live/unit switching. No code changes needed to support it.
3. **Separate conftest per directory** — `tests/unit/conftest.py` doesn't conflict with `tests/conftest.py`. pytest fixture resolution handles it naturally.
4. **ruff --fix** for unused imports — saved manual cleanup time. Always run after writing code.

## Gotchas

1. **GitHub token regex**: Real tokens have variable length (not exactly 36 chars after prefix). Use `{20,}` not `{36}`. Test tokens must match the actual format.
2. **Logging filter vs format args**: Python's `logging.info("msg %s", arg)` stores the token in `record.args`, not `record.msg`. A filter must sanitize both `record.msg` AND `record.args` for format-string-style logging.
3. **pip install -e ".[all]"** fails in this repo because there's no Python package source (it's a test-only project). Install dependencies directly: `pip install pytest pytest-asyncio httpx respx pydantic`.
4. **Previous agent branch conflict**: The issue had a prior WIP agent run that pushed a placeholder commit to `agent/issue-1361`. Always `git fetch` + check remote state before pushing.
