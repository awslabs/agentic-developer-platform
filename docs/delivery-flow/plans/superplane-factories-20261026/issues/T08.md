## The problem in plain terms

Operators need a reliable way to acquire SkyPilot capacity for approved queued demand. The current implementation does not yet provide this outcome under the four-layer factory contract.

**The fix in one line:** Acquire SkyPilot capacity for approved queued demand.

## Description

- **Parent / reports to:** https://github.com/aws-e/adp/issues/8950.
- **Delivery owner:** ADP delivery-flow coordinator assigns the SPF-T08 implementer; the coordinator owns integration and finding closure.
- **Size:** Medium. **Workstream:** capacity. **Release batch:** R2.
- **Completion boundary:** Merged implementation and its relevant tests; live deployment/acceptance is owned by batch R2 release/verification stories.
- **In scope:** Bind queued training demand to governed SkyPilot allocation operations, approved provider/region/fallback constraints and existing ownership inventory. Observe allocation progress and provider request IDs. Release idle or cancelled owned allocations under the run policy.
- **Out of scope:** Other factory/provider/application outcomes owned by sibling stories; current workspace recovery remains under #6970.

## Impact analysis

No infrastructure is changed by filing this issue. Preserve existing identity, approval, budget, ownership and execution history. Provider or component failure must remain observable without duplicate paid resources.

The failure in AC-02 can otherwise produce false readiness, lost progress or incorrect resource ownership. No new cloud spend limit is invented here; live actions require the selected existing authority/budget and are bounded by their operation deadline.
