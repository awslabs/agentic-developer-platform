## The problem in plain terms

Operators need a reliable way to deploy one compatible training and capacity release. The current implementation does not yet provide this outcome under the four-layer factory contract.

**The fix in one line:** Deploy one compatible training and capacity release.

## Description

- **Parent / reports to:** https://github.com/aws-e/adp/issues/8950.
- **Delivery owner:** ADP delivery-flow coordinator assigns the SPF-R02 implementer; the coordinator owns integration and finding closure.
- **Size:** Medium. **Workstream:** release-acceptance. **Release batch:** R2.
- **Completion boundary:** Deployed and live-verified for the named operation; required blocked/not-run cases remain open.
- **In scope:** Build changed R2 components once, deploy their compatible schema/API/worker/UI/CLI/profile set and enable training only on qualified workspaces. Reuse the R1 platform and unchanged artifacts. Verify current Gateway/scheduler compatibility without pausing unrelated shared deployments.
- **Out of scope:** Other factory/provider/application outcomes owned by sibling stories; current workspace recovery remains under #6970.

## Impact analysis

No infrastructure is changed by filing this issue. Preserve existing identity, approval, budget, ownership and execution history. Provider or component failure must remain observable without duplicate paid resources.

The failure in AC-02 can otherwise produce false readiness, lost progress or incorrect resource ownership. No new cloud spend limit is invented here; live actions require the selected existing authority/budget and are bounded by their operation deadline.

## Deployment

Execute only the named batch/acceptance operation through maintained entry points and the verified C08 manifest. Reuse unchanged artifacts; do not start an additional full deployment for a verification-only story.

Gateway continues normal automatic builds/rollouts. Verify current serving Gateway and scheduler compatibility at release time; preserve unrelated changes and never restore a historical Gateway merely to match an old plan. Keep Terraform resource ownership and existing state until an explicitly verified transfer.

Recovery uses durable intent, provider IDs and current execution fencing. Retain shared/adopted resources and uncertain cleanup exposure. Handoff owner is the epic's release/acceptance coordinator; implementation merge alone is not deployed acceptance.
