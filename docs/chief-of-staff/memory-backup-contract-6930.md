# Chief-of-Staff #6930: gateway memory and Crew checkpoint contract (ARC-03)

This is an **implementation contract**, not evidence of an AgentCore memory resource, S3 archive or installed Crew. Keep portable shared memory independent of the owner's native Crew home. See the [source claim matrix](source-audit-6930.md), [role-free workload decision](runtime-boundaries-6930.md) and [failure walkthrough](boundary-walkthrough-6930.md). The upstream native file inventory and version compatibility must be revalidated under the pinned #7201 image before implementing capture; no Crew fork, memory plugin, S3 Files mount or local event-stream projector is selected.

## Gateway AgentCore adapter — #7210

| Contract | Exact gateway behavior and readiness boundary |
|---|---|
| Target/config | An authorized operator selects a **real** AgentCore memory ID, region, semantic-memory strategy ID and expiry/retention configuration for a named target via private deployment config. The gateway uses its own trusted workload identity and `bedrock-agentcore` client in that configured region; no Crew/client AWS credentials. Missing/mismatched region, unknown strategy, unavailable memory, IAM denial or account mismatch fails closed for writes and reports recall as **unavailable**, never empty. Verify resource/strategy IDs and policies on the actual target; this document supplies none. |
| Supported APIs | The inspected local boto3/botocore `1.43.111` runtime model exposes `CreateEvent(memoryId, actorId, eventTimestamp, payload, sessionId?, clientToken?)`, `RetrieveMemoryRecords(memoryId, searchCriteria, namespace?, maxResults?)`, `ListMemoryRecords`, `GetMemoryRecord` and `DeleteMemoryRecord`; the control client exposes `CreateMemory`/`GetMemory`. Runtime service-model SHA-256: `81f7212d449ee759c1d9afbcae19b74e995264cbe436a34f9f02efe6ef30e8c5`; control model: `4fc4d35227405cf0167886e17bea60fc32c5eb5eff29b3cba29aba47bd9fd336`. This verifies **local SDK shapes**, not enabled service features or account permission. No gateway request may choose memory ID, region, namespace, strategy or actor. |
| Scope and recall | Map authenticated tenant/user to one stable opaque actor and owner namespace in protected gateway data; derive session from verified turn binding. Check membership/consent at **every** recall and management call. Use configured semantic strategy with bounded `searchCriteria.searchQuery`, `memoryStrategyId` and `topK`; explicitly scope `namespace`, filter/adjudicate result owner/provenance and trim by tokens before inserting marked **untrusted** context into each supported model adapter. Support only audited gateway model routes carrying a verified human/session and privacy flag; unknown formats/client bypasses do not capture or receive a false memory claim. Existing streamed tools, cancellation, output schema, metering and budgets remain on the same inference path. |
| Capture and acknowledgement | For an eligible completed human turn, persist a gateway-owned idempotent capture record **before** acknowledging `captured_for_processing`; use trusted tenant/owner/session/turn and canonical request hash as the stable dedup key. A worker invokes `CreateEvent` with a deterministic `clientToken` and processes retries with bounded backoff and captured-error status. Event acceptance is **not** extracted-record visibility. Report `available_for_recall` only after a read/list by scoped source marker or explicit readback verifies the resulting record and current correction/deletion fence; otherwise `pending`, `failed` or `unavailable`. The normal assistant reply is never a save receipt. Service-side extraction/processing latency and spend are measured separately from gateway inference. |
| Request budget | Gate first rollout on #7175's matched model/turn/region baseline; proposed additional recall **p95 ≤ 250 ms** at the gateway and bounded injected context (configured per route) are acceptance targets, **not measured results**. Use a finite timeout within the turn's remaining deadline, emit partial/unavailable coverage if recall fails, and never transform an AgentCore outage into an empty memory store. Capture is async and does not extend foreground model deadline; visibility lag is measured from accepted gateway capture to verified available record at #7215/#7217 before any freshness promise is made. |
| Legacy migration | #7210 inventories the existing owner-partitioned DynamoDB `chat_memory.py` rows and their ACL/TTL/version, dry-runs per-owner counts and quarantines missing/conflicting ownership. Only currently authorized, non-expired records migrate with source/version provenance and deterministic dedup keys; confirmed correction/deletion tombstones take precedence. During a bounded opt-in cutover, deduplicate gated legacy/AgentCore reads; never silently dual-write or infer sharing from tenant equality. Rollback disables new capture/recall, retains an auditable migration journal and deletion fences, and does not silently revive an old row. Existing history/artifact services remain authoritative for exact transcripts/files. |

The exact supported strategy, API response fields, extraction visibility and provider policy are **target prerequisites for #7210**, not claims established by the SDK shape alone. If records cannot be associated with a source marker after asynchronous extraction, keep the receipt pending/unavailable and require a reviewed alternative before claiming a completed save. ARC-04 specifies correction and late-ingestion precedence.

## Consistent Crew home and direct S3 checkpoint — #7202

| Inventory class (relative to owner-scoped `KIROCREW_HOME`) | Capture/restore requirement |
|---|---|
| Preserved, after quiesce | V1 `workspace/memory/` markdown, `memory.db`, named `memory_stores/`, `lessons.jsonl`; V2 member `memory.db`, revisions/proposals, `trust/member-rules/`, `members/*/briefing.md`, preference/project guides; supported dashboard conversation/transcript state, workspace files and artifact organization required by the approved restore fixtures. Identify the **actual pinned-version paths** rather than assuming the V1 layout covers V2. |
| Reconstructed | Rebuildable V1 FTS `memory_index.db`, FAISS/derived embeddings and Knowledge Library indexes **only if** the fixture proves their source documents are preserved and recreation works offline on the pinned image. Otherwise preserve the corresponding databases with an online SQLite backup. |
| Separately managed | ADP history/artifacts and gateway AgentCore user memory, service-side credentials/identity, owner/machine enrollment and provider config. They are **not** extracted from restored Crew snapshots into shared memory or reused from the former target. |
| Excluded | Managed secrets and token stores, AWS credential files, sockets, PIDs, lock/temp files, mounted token directories and process state. Generic redaction is insufficient; the manifest lists every included path and exclusion, rejects unsafe symlinks/path traversal and verifies that a selected source directory contains no unclassified file. Stop on unknown paths instead of silently dropping or uploading them. |

#7209 externally quiesces native writers before #7202 stages all approved files; use SQLite online backup or a proven transactionally consistent filesystem snapshot for **each** database and ensure the markdown/files capture belongs to the same quiesced generation. Native Crew snapshots alone omit some dashboard/organization data, and redaction is off by default at the reviewed source revision. Do not copy live `.db`, `-wal` and `-shm` independently. A timeout, inconsistent inventory or full owner volume is a visible failed capture. Proposed cadence: attempt after completed activity and at most five minutes while active, one helper per executor, warn if the last **verified** capture exceeds ten minutes; these are proposed operations bounds to validate with #7215/#7217, not an established recovery point. Loss of newer unsynced local writes remains possible.

Use a separate role-free helper with gateway-issued short-lived presigned **direct S3** requests only for unique archive and manifest keys. Complete/reconcile multipart uploads, validate full SHA-256, approved inventory, sizes and exact **version IDs**; an ETag is not an archive hash. The helper cannot publish success by uploading. #7221 owns canonical `(tenant, user)`/generation in the **existing gateway control database**. #7202 adds one additive `crew_checkpoints` migration in that same database: checkpoint ID, immutable owner/generation/sequence/idempotency key, status, exact archive/manifest bucket/key/version/checksum/size, native/profile/schema versions, capture/verified times and retry/retention metadata. The canonical owner row gains `latest_verified_checkpoint_id`; do not create an alternate executor inventory or second migration owner. Coordinate the migration after #7221 and before #7209.

**Cross-store fencing:** the fast session lease may be held in DynamoDB, while #7221's authoritative owner generation and #7202's pointer are in the gateway control database. A DynamoDB lease read **cannot** atomically authorize a PostgreSQL pointer update. #7221 must make target-switch/fence advance the authoritative owner generation in a control-database transaction, then invalidate any cached/DynamoDB lease. For every privileged gateway call, recheck current generation against that database; stale or unavailable generation is denied, not served from a cache. #7202 publishes only after S3 verification, in **one control-database transaction** comparing the current owner/generation/previous pointer and advancing checkpoint status plus pointer. A lost response reconciles by the stable key; upload-success/DB-failure leaves an unreferenced candidate, never `Synced`. Old helper grants expire and cannot delete verified objects; old-version overwrite cannot alter the exact stored version. Exact-version restore pins retention, validates archive/inventory/compatibility onto a new volume **before** Crew starts, and never overwrites an existing nonempty home without explicit disposition. Deletion/retention must fence in-flight publishing and reconcile versioned S3 objects.

**Verification owners:** #7210 supplies emulator tests for spoofed actor/namespace, capture dedup, denied/corrected/deleted records, migration/quarantine and unavailable recall plus mounted adapter tests. #7202 supplies mounted-volume/SQLite consistency, omitted native path, excluded secret, partial S3/DB, stale generation and exact-version restore/retention tests. #7215 evaluates repository contracts, #7223 host handoff, #7217 live cross-assistant/container–EC2 continuity after an authorized target is bound. No test of the proposal text alone establishes service isolation, S3 object durability or deployed latency.
