# Chief-of-Staff #6930: boundary and recovery walkthrough (D02)

This is a **design-time manual walkthrough** of the [pinned architecture](https://github.com/aws-e/adp/blob/825583373982de3e370f121544c4a18026454077/docs/chief-of-staff/architecture.md), not an executed fault injection or a deployment receipt. Source paths and byte hashes for the existing chat identity, memory and model routes are in the [D01 source audit](source-audit-6930.md). Crew admission, checkpoint metadata and AgentCore memory below are proposed integration contracts; no row claims that those routes exist today. The implementation owners must turn these cases into executable repository and live checks before acceptance.

| D02 walkthrough | Enforcement and atomicity point | Observable outcome and independent oracle | Implementation and evidence owner |
|---|---|---|---|
| t1 — Valid owner, two sessions and a coherent save | Trusted ingest derives tenant/user from the verified connection; the gateway checks the owner/session and current `(owner, executor_generation)` before admitting a turn. #7203 serializes turns per session while allowing fair progress across that owner's sessions; #7209 quiesces the writer before capture. #7202 stages a coherent SQLite backup and approved home inventory, checks archive/manifest checksums and exact S3 versions, then **in one database transaction** checks current generation/sequence, verifies the checkpoint and advances the owner-level latest pointer. | The session receives only its own turn and response; another session can progress without receiving that response. A `Synced` receipt names the verified capture time/checkpoint and exact object versions; an independent pointer read resolves the same manifest/archive. Newer local writes or AgentCore processing are **not** implied by `Synced`. | #7198/#7199/#7203 for admission and scheduling; #7209 for quiesce; #7202 for save/receipt; #7215 and #7217 for repository/live checks respectively. |
| t2 — Forged user, switched owner or stolen helper token | Gateway derives owner from verified human/session or registered workload binding, **never** from a prompt, forwarded owner header, S3 key or caller-supplied generation. #7221/#7199 bind executor and lease generation; #7198 restricts the helper to its owner volume and upload scope, and the gateway rechecks current authority on each request. A helper upload credential is not a memory/admin capability. | Denial at ingest, gateway resource check or helper/admission boundary; no cross-owner read, upload publication or response. Audit an owner-scoped refusal without echoing a token; independently inspect owner row, object scope and denial. A leaked same-owner helper credential remains a risk within its bounded scope and must expire/revoke with the generation. | #7198/#7199/#7221, #7202 for checkpoint API; #6937 for foundation denial, #7215/#7217 for Crew denial. |
| t3 — Concurrent turns, cancellation and end | #7203 queues per-session turns in order under one owner lease, applies per-owner fairness across sessions and matches response to original session/turn. #7209 checks cancellation and lease before dispatch, tool calls and terminal publication. End fences the affected session immediately; last-session end additionally triggers a bounded owner checkpoint/idle transition, not deletion of other sessions. | Concurrent same-session turns do not interleave or duplicate execution; another session is not starved. A canceled or ended turn receives one terminal outcome and cannot publish later chunks. The other owner's session remains unaffected. Inspect turn IDs, cancellation fence, owner lease and response receipts. | #7203/#7209, #7215 repository race checks and #7217 live checks. |
| t4 — Old writer after owner target switch or expired lease | #7221 alone advances the stable owner/executor generation transactionally when handing off; #7199 fences the old run. #7202's trusted publisher rechecks that generation **in the same control-database transaction** that updates checkpoint status and owner pointer. #7209 refuses subsequent old-run tools, events, response chunks and restore-side writes. Do not use token TTL or S3 upload completion as a substitute for fencing. | Old publication or response is refused; the newer pointer and new session output remain unchanged. An old candidate may require orphan cleanup but cannot become latest. Read both generations, pointer and object versions after the race. | #7221/#7199/#7202/#7209; #7215 and #7217 exercise races. |
| t5 — Failed upload, lost acknowledgement or DB commit failure | #7202 uses a stable checkpoint ID/idempotency key; upload to unique keys, complete multipart parts, independently validate both exact object versions, then conditionally publish. S3 and the control database have **no shared transaction**: retry reads checkpoint, objects and pointer and converges on the same ID. Failure before upload completion never sets `verified`; commit failure after successful upload leaves an unreferenced candidate, not a visible latest pointer. | `Sync failed` or pending/unknown-effect status rather than `Synced`; prior verified pointer persists. The reconciliation worker checks S3 versions and DB row before retry or orphan cleanup; a lost response cannot start a new blind checkpoint or erase the candidate. | #7202 for uploader, API and reconciler; #7209 for displayed lifecycle, #7215/#7217 for injected failures. |
| t6 — Restart after incomplete save or incompatible restore | #7209 resolves the owner-scoped **verified** pointer, not the newest uploading row, and #7202 pins exact S3 object versions against retention; validate inventory, checksums, schema/Crew compatibility and extraction paths before activating a fresh, isolated volume. A missing/corrupt latest object is a visible recovery failure; fallback needs an explicit older-capture-time decision. | No empty-home success, half-restored SQLite or silent latest-pointer regression. Show last verified capture time, restored checkpoint/version or failure; independently compare restored inventory and stored manifest before enabling new turns. | #7202/#7209, #7222 for host handoff; #7215/#7223/#7217 for repository/host/live evidence. |
| t7 — Correction/delete versus late extraction and restored old text | #7210 assigns a server-side correction/deletion generation and explicit-user provenance at the gateway before acknowledging a change. Every queued capture, AgentCore processing retry, cache read and extraction from restored Crew content must check that fence. Previously recalled text is not a new explicit save; #7202 keeps backup erasure/retention separate from shared memory deletion. | Old pending or replayed content cannot overwrite a correction or silently re-create a forgotten shared memory. Inspect/export/forget reports which stores were affected and which Crew-local files were **not** erased. A new, independently authenticated explicit save after deletion may reintroduce content under a new generation. Inspect the gateway fence and AgentCore result after processing completes, not only a model reply. | #7210 gateway memory/governance; #7202 backup retention; #7215/#7217 negative checks. |

Walkthrough method: for each row, substitute a different trusted owner, a second session, a changed generation, a failed S3/DB step, or a stale memory operation and follow the specified read/write authority from entry to durable receipt. Compare the proposed result with the existing [identity and authorization](architecture.md#identity-and-authorization-contract), [checkpoint publication](architecture.md#checkpoint-metadata-and-atomic-publication) and [correction/deletion](architecture.md#corrections-deletion-and-independent-memory-authority) contracts. All seven rows have an enforcement point, refusal or receipt oracle and named implementer; **these documentary assertions were reviewed against the architecture and source audit, not run against a live target**. The follow-on stories must select real fixtures, negative tests and target evidence. Unresolved ARC-01–07 decisions and the D03/D04 plan remain open.
