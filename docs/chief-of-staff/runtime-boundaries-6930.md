# Chief-of-Staff #6930: Crew workload and owner-session decisions (ARC-01/02)

**Selected contract for implementation review, not deployed proof.** The [foundation sandbox](architecture.md#trusted-coordination-and-sandbox-isolation) is an intentionally role-free executor; model-run shell tools can inspect their own process, environment and mounted credentials. An in-pod IRSA token, a loopback SigV4 proxy that reads it, or an environment-hidden signing key therefore cannot isolate AWS authority from Crew. Choose **role-free Crew model pods**, a trusted gateway for model/data calls, and a **separate** checkpoint helper that receives only short-lived checkpoint-specific upload authorization. This supersedes the proposed in-pod IRSA/execute-api exception in #7198 and the in-pod SigV4 re-signing proxy in #7200; their owners must amend those issue contracts before implementation. It does not change the already implemented ephemeral path.

**Private-V2 admission check:** native Crew private V2 requires `agent.sandbox=auto` with usable Linux namespaces; an unconfined mode, disabling the sandbox, or silently dropping unsupported MCP tools is not an acceptable workaround. #7201 must exercise a real pinned Crew profile under the proposed non-root UID, seccomp, read-only-root plus explicit writable home/scratch mounts, and the actual supported namespace policy. If unprivileged namespaces or filesystem writes fail, #7198 owns the smallest separately reviewed pod-profile fix without relaxing ephemeral admission; #7201 reports an incompatibility and blocks Crew selection until both the gateway provider route and native sandbox pass. Model tools may write the bound owner's home but may not reach a helper credential or another owner's volume. A source-only policy fixture cannot establish the installed kernel/CSI behavior.

## One-owner session and handoff contract

A persistent Crew executor is isolated across **human owners and tenants**, not across that owner's conversations. Default each conversation to private *presentation*: turn and response histories, tool grants, streamed chunks and cancel/end controls are scoped by session/turn even when the same owner authorizes access to shared Crew home files and native memory. Do not promise filesystem isolation between two sessions in one Crew process; the UI must disclose this sharing before choosing Crew. No team member or guest joins a live owner executor merely by sharing a document. Revalidate current owner membership and tool grants on every request and when switching targets; old remembered content never conveys execution authority.

#7203 owns one exclusive `(tenant, user)` executor lease with a monotonic generation from #7221. The gateway accepts one active turn per conversation in FIFO order and runs a bounded fair scheduler across conversations (round-robin ready sessions with a finite per-session turn budget); one busy/long turn cannot monopolize the owner runtime. A native Crew operation that cannot safely yield must be canceled/isolated or surfaced as a blocked short turn, **not** advertised as fair progress. Route every event/result and replay cursor by original session, turn and generation. Cancellation fences that turn before response or effect publication; explicit end fences only that conversation, aborts pending turns and preserves other active owner sessions. Final session end quiesces/captures if possible, then revokes the owner run/lease and idles; checkpoint failure remains visible and cannot be described as synced. A target switch fences the old generation and helper before a successor can publish or serve; one active writer per owner, including across EC2/container. A surviving EC2 developer session is not stopped when its Crew session ends.
