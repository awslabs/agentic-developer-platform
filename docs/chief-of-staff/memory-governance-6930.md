# Chief-of-Staff #6930: shared-memory governance (ARC-04)

This is a **selected gateway contract**, not a claim that AgentCore, legacy memory or Crew already implements it. [AgentCore capture and checkpointing](memory-backup-contract-6930.md) are separate stores; Crew's private-V2 native file rules are **not** a human tenancy boundary or an ADP shared-memory policy. The gateway can govern interactions it sees and managed checkpoints, not unseen local edits. Validate these controls under #7210/#7202 and the [D02 failure walkthrough](boundary-walkthrough-6930.md) before enabling capture.

| Boundary | Decision and observable outcome |
|---|---|
| Automatic eligibility | Only a completed, newly authenticated **human utterance** on an audited supported gateway model route may seed automatic learning when current consent permits, session privacy is explicitly known and source role/turn ID are trustworthy. Default unspecified privacy, temporary/incognito/private sessions, revoked owners, tool/document/assistant/system text, repeated prompt history, model-inserted recalls and internal extraction are **ineligible**. A private request also omits shared recall unless that owner explicitly opts in for that session. Where an unchanged client omits trustworthy turn/privacy metadata, skip automatic capture (and disclose coverage); do not add a mandatory Crew field or reinterpret the entire prompt as a fresh user statement. |
| Provenance and explicit precedence | Persist gateway-side, owner-scoped capture ID, trusted session/turn/source, source digest, event ID, privacy/consent snapshot, originating context revision, memory subject/key and monotonic **correction/deletion epoch**. Classify a user-directed management action through an authenticated ADP inspect/correct/forget API, never by a model claiming the user asked it. Explicit correction outranks inferred preference/fact regardless of async arrival order; a lower-trust ambiguous update becomes a pending proposal or is dropped. Historical evidence remains distinguishable from current truth and cannot authorize tools. |
| Transaction and late ingestion | A correction/forget first atomically increments the subject epoch and records a durable correction/tombstone in the gateway control store; admission, worker retry, read cache and **publication** all compare current epoch before surfacing a candidate. Queue entries keep the epoch at capture; work from an older epoch is suppressed. AgentCore APIs do not supply a cross-service transaction with this store: even if late service extraction creates a record, gateway recall filters by the durable fence and a reconciler deletes stale versions; a service response alone never reports correction success or `forgotten`. Invalidate cached results by epoch and re-check membership per recall. An unavailable fence store fails closed for memory publication/recall. |
| Restored Crew content | #7202 restores local application files only; it never auto-imports them to AgentCore. A restored transcript, earlier recalled context or generated summary is tagged **historical/untrusted**, not a new explicit user utterance. If adapter provenance cannot distinguish restored text from new input, stop automatic learning on that route. An independently authenticated **new** explicit user save after the forget epoch can recreate a fact with a new revision; a background re-extraction or replay cannot. Tests restore an old nonempty Crew home, replay the exact old words, race late event processing, then verify no deleted shared memory becomes visible. |
| Inspect/export/forget | Authorize against the verified owner and current membership for every record ID/page; never accept caller-supplied AgentCore namespace, arbitrary object path or teammate scope. `inspect` returns current record, source/provenance, revision and capture-vs-available status; `export` paginates current authorized records with retention/coverage and separately lists managed checkpoint metadata rather than claiming a complete local-file export. `forget` fences gateway memory immediately, removes matching queued/cached/legacy entries and requests deletion of **all known** AgentCore record/event IDs; retry and independently verify absence through list/read before marking backend deletion complete. Partial service errors report `pending`/`failed`, not success or zero records. Gateway forget cannot erase unseen Crew files, owner workspaces, backup archives or third-party copies; show separate #7202 checkpoint retention/purge or broader reset with its own completion evidence. |
| Retention and erasure race | An authorized operator configures bounded AgentCore event expiry, extracted-record policy, capture/outbox/cache and legacy row retention plus managed checkpoint/S3 object-version retention. If the service cannot meet the required record deletion/expiry guarantees, the feature cannot claim those guarantees or enable a false full erasure control. Keep a minimal owner/subject epoch tombstone while any older queued event, legacy record, archive or restore can reappear; expire it only after proving those sources and in-flight workers are drained/purged. On owner removal, fence admission and pointer publication before deleting service records and versioned S3 objects; reconcile delayed S3 completions, partial deletion and service eventual visibility. Protect against stale reads through gateway filtering even before remote deletion finishes. |

**Failure walkthrough to check under #7215/#7217:** (1) private session and ambiguous request produce `capture_skipped` with a source-specific reason, not an invented saved preference; (2) malicious document or tool text saying “remember me” is ignored; (3) explicit correction before old event completion remains current in inspect/recall and the old record is reconciled; (4) forget racing late extraction, cache fetch, old Crew restore and an old helper leaves gateway recall empty **because of a tombstone**, not because a model ignored it; (5) a fresh, independently authorized explicit save may create a new revision; (6) cross-owner/forged record IDs and revoked membership are denied without enumeration; (7) backend delete outage leaves a visible pending deletion and retains the suppression fence. A passing gateway fake proves only the fake's behavior; target evidence must inspect actual AgentCore read/list visibility and owner-isolated routes.

#7210 owns gateway provenance, epoch, queued processing, controls and legacy migration; #7202 owns checkpoint retention/restore and scoped local reset. Shared context owners #1287/#1283/#1345 may consume authorized records but cannot bypass this gateway fence. Exact retention periods and backend visibility must be bound to a real target and reviewed before promising legal/data-erasure completion. No claim is made that an unmodified Crew client sees local private-file deletion through this gateway API.
