# Native credential delivery on a laptop

The credential broker lists metadata and proxies allowlisted requests without revealing stored secrets. Role assumption and file materialization never return credential values through generic tool results, receipts or downloadable artifacts. They require the separately configured, default-off native issuer and a private host on a supported Linux x86_64 laptop. This is a source/installation guide, not evidence of a deployed issuer or approved provider fixture.

Before using this path, sign in as the credential's owner with the regular native CLI login, obtain explicit consent for the specific credential and operation, and run `adp credential host-setup` to install the pinned runtime. The browser approval page must use the deployment's separately configured browser OAuth client; a worker, forged tenant selector, agent ID or Task ID cannot substitute for your native session. The account owner supplies the browser app and interactive approval. If the issuer or approval page is not configured, do not fall back to generic role/file tools.

For a **local terminal** use, run `adp credential use --help`. Select an owned credential, the operation, and the exact executable, working directory and lifetime. For an **MCP client** use, first run `adp credential host-register --help` to register an immutable named profile for one selected executable and credential. Then run `adp credential host-serve --profile NAME` in a separate terminal as the signed-in human. The coordinator uses its own native session, not the MCP worker's token. Only when that profile is ready does MCP advertise `credentials___assume_role` or `credentials___materialize` locally. A request opens `/credentials/native/RECEIPT_ID` in your signed-in browser, where you inspect the credential, exact command, duration and private recipient before approving or denying. Browser denial or revocation stops delivery; the page does not receive credential material.

An AWS role session is exactly 900 seconds; file use can be shorter and cannot exceed 900 seconds. Only the selected child receives short-lived credentials. The host supervises the child and cleans up its volatile sink after expiry or failure. Read an uncertain result with its original `operation_ref` using `adp___operation_status` (or `adp credential delivery-status --request-id` for local use). Do not resubmit an unknown request: recovery is metadata-only, and artifacts never return private credentials. Revoking consent under Settings → Credentials prevents subsequent issuer use; already-issued STS credentials cannot be remotely shortened.

Offline regression checks from `modules/gateway` include `uv run --no-sync pytest -q -n 0 tests/cli/test_native_credential_handoff.py tests/cli/test_adp_native_credentials.py`. The separate serial host-process suites use synthetic credential values and never assert protected provider delivery. Live acceptance requires an authorized protected deployment, owned fixtures, interactive consent and independent provider/evidence readback supplied by the coordinator; do not create infrastructure merely to run these tests.
