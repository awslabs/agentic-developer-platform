## Development with limited provider data

The [test-data strategy](../../delivery-flow/plans/atlassian-adapters-8445/test-data-strategy.md) supersedes earlier full-fixture and authenticated-proof prerequisites for independent development. Stages 1–7 use generated controlled data plus actual deployment verification. #8446 supplies capability discovery and the controlled probe; #8447 supplies generated DB/service fixtures; each feature story owns its cases. #8454 automates minimal live data creation/readback/cleanup using existing grants. No human is assigned project/account/dataset preparation. Provider schemas remain provisional where unobserved, and real-provider activation stays disabled until the corresponding authenticated proof passes. A known incompatibility still requires a fix.

Native dependencies require the predecessor's reviewed implementation/phase handoff; they do not require full final live acceptance before independent successor code can start. Missing extra users/sites, provider consent, data or model access remains in a separate pending-live ledger and holds only the affected live claim/handoff. All original final criteria and IDs remain mandatory; a controlled pass is never a live pass.
