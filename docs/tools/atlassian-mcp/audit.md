# Repository audit for Atlassian MCP design v5

## Boundary, method and reproduction

Audit baseline: `0ebf98389d609aa553679497250572b8a13bdb07`, fetched main on 2026-10-20. The baseline has **11,562 tracked artifacts** and **135 Alembic migrations**, including branched histories and merge revisions. The migration graph resolves to `122_product_handoff_callbacks`. This is a source/build/deployment-entry audit, not live infrastructure inventory or acceptance evidence. No AWS state, provider-authenticated state, deployed hashes or installed-client context was observed.

The attached ledgers enumerate **every tracked artifact**, not a representative sample:

| Artifact | Contents |
|---|---|
| [inventory.tsv](inventory.tsv) | Every tracked path, Git blob/object identity, component, include/conditional/exclude disposition, explicit reason, entry type and selected-reference hits. |
| [entrypoints.tsv](entrypoints.tsv) | Every detected workflow, local action, image/package build, Terraform/HCL, Kubernetes/Helm manifest, executable/shebang/main-guard script or scripts/bin candidate; includes excluded unrelated entries. |
| [migrations.tsv](migrations.tsv) | Every revision, parent/merge dependency and file, in deterministic parent-before-child order. No assumption that lexicographic filenames determine final state. |
| [design_audit.py](design_audit.py) | Reproducible immutable-source scan and exact ledger comparison; no runtime effects. |

Every `.github/workflows` file is included in the entry ledger. Starting from the affected release/test workflows, the scan recursively follows local reusable workflows/actions, including gateway migration/smoke/live/CLI checks and publishing actions. Searches cover the entire tracked tree for Atlassian/Jira/Confluence, shared tool/authorization/catalogue and OAuth connection references. Explicit module boundaries add transitive authority, SQL history, client, infrastructure, release and test files that do not contain those terms. Conditional entries remain accounted for: they are not silently dropped.

The search has **37 selected-reference exclusions**, all listed individually in `inventory.tsv`; they are historical/adjacent docs or prior audit artifacts, including the older user-vault design and AgentCore samples. They inform terminology or context but are not executable v2 implementation/release surfaces. Runtime shared consumers are instead conditional. Inclusion means a component belongs in the design/compatibility audit, not that every file should be edited. Broad gateway internal/auth and all migrations deliberately over-include to avoid missing authorization/schema dependencies. No claim is made that every line of every unrelated excluded file was manually reviewed.

From the repository root, with Python 3 and Git and the baseline object available:

```bash
python3 docs/tools/atlassian-mcp/design_audit.py
python3 docs/tools/atlassian-mcp/verify_design.py
python3 scripts/check-public-docs.py
```

The first command recomputes all rows and errors on any inventory difference; it prints exact disposition/entry counts. The second checks local document anchors, source-file/line links and citation definitions. The public-doc checker operates on tracked files: stage intended artifacts before using it on a new document. `--emit-patch` on the audit script prints replacement ledger patches for use with `apply_patch`; it does not write runtime files or mutate source.

## Data and IAM audit

All migration files were enumerated and their revision/parent graph parsed. Relevant SQL operations/models were inspected before proposing additions: `004_user_identities_and_credentials.py`, `007_scope_relaxation.py`, `097_oauth_connection_pointer.py`, `109_oauth_scope_snapshot.py`, `110_oauth_provider_binding.py`, `111_oauth_reconnect_resources.py`. Later product migrations reference credential IDs but do not supply the proposed OAuth setup/recovery state. Do not rewrite `org_id` history; new API/table names use `tenant_id`. Additive migration tests must cover a legacy-only DB, mixed legacy/v2 and rollback with pending jobs.

`modules/tools/platform/bootstrap/main.tf:12` defines the existing execution DynamoDB table: partition key `execution_id`, `cleanup-due` GSI with `cleanup_partition` and `next_cleanup_at`, encryption, PITR, retention TTL and destroy protection. `ExecutionStore` already owns operation rows. Extend typed due-work fields in that table, not a second operation store. SQL outbox is only for gateway/vault lifecycle because those transactions are relational. Keep unresolved rows from TTL retirement.

No new S3 bucket is proposed. Existing source/state/evidence/artifact buckets and their scoped publishing mechanisms are inventoried under platform/tools/gateway infrastructure. Use existing private evidence references and retain raw fixtures/tokens out of public docs; response hashes are not raw acceptance records. No ADP per-user OAuth-token secrets are added. `oauth_setup.py` and `modules/gateway/infra/oauth-identity-policy.tf` own deployment app-secret naming; v4 retains Identity token storage and adds a separately scoped adapter identity.

Proposed IAM changes are resource-specific: core retains setup/consent/revocation APIs; the adapter has a separate role for configured Identity workload/provider token retrieval after core authorization, with no core SQL, app-secret or provider-administration permission. Gateway can call scoped Identity workload/provider APIs and access only required deployment app secrets with required KMS permissions, SQL consumer uses the same authorized gateway boundary, facade reconciler gets due-index/operation updates and invoke permission only on the new settlement route, target role invokes only the exact private mediator route, interceptor verifies the pinned claim signing key. API Gateway resource policies, execute-api caller identity, KMS key policy and IAM identity policy must agree. Reuse private edge/VPC connectivity; do not expose an unauthenticated public mediator or wildcard target URL. No new raw Atlassian secret permission for scaledjob, ARC runner, webhook-ingress, client laptop or AgentCore target. Hosted workload access, if used, resolves original-human Task authority and requires no machine grant. Terraform tests must reject extra resource/action scope.

`modules/gateway/infra/oauth-identity-policy.tf` currently grants named built-in OAuth provider/app operations; MCP provider/configuration and supported revocation permissions still need proof and scoped updates. User-token refresh remains inside Identity; no custom-vault token rotation permissions are proposed. `modules/tools/platform/bootstrap/main.tf` also contains resource-policy `Resource="*"` inside KMS key policy documents; do not blindly copy that into new IAM identity policies. Scope new permissions to the exact approved key/secret/API/table resources. No IAM mutation was performed during audit.
