# S21 — per-location suppression review and CVSS reconciliation

Reviewed 2026-09-25 against base `1b75bce54` and the source repair accompanying this document. This is the location-by-location follow-through for [ledger sections 8.D and 8.E](S21-evidence-ledger.md#d-all-13-suppressed-criticalhigh-records--locations-as-published). It does not replace the original scan inventory or claim a clean image/release. No scan, build, deployment, live request or independent identity probe was run for this review.

The 13 suppressed records are **not thirteen false positives**. Eight server-side call sites needed redirect refusal; five have a specific applicability disposition below. The repair adds `redirect: 'error'` at those eight calls. Existing in-source markers remain; no marker was added, and no rule configuration, global suppression or baseline was changed. Source delivery remains distinct from merge, deployment and final scan acceptance.

## Evidence reused from S04 and S05

[S04 PR #5774](https://github.com/aws-e/adp/pull/5774), merged as `ebde4b403cf8050e5695cce3ad64b62215dafba6`, established that Node fetch forwards custom authentication headers across redirects. Its [reviewed outcome](https://github.com/aws-e/adp/issues/5603#issuecomment-5784008126) covers its five assigned sites and the shared URL-credential guard. It does **not** establish redirect safety for the six GitLab/vault sinks below, which still used default-follow behavior in the reviewed base.

[S05's disposition](S05-disposition.md), merged through [PR #5704](https://github.com/aws-e/adp/pull/5704), distinguishes a fixed initial GitHub origin from redirect behavior. Its recorded runtime experiment found standard `Authorization` stripped across origins; its three locations nevertheless received response-origin checks. Those three locations are different from the two GitHub sinks below. Neither S04 nor S05 is used as blanket acceptance for another location.

`validateBaseUrl` parses and normalizes the initial origin, rejects URL credentials, enforces protocol options and blocks listed literal loopback/metadata/link-local addresses. It does not validate redirects or resolve arbitrary DNS names into an address allowlist. Vault's `pinHost` is parsed from the same supplied config URL, so it is **not an independent trusted-host allowlist**. The repair relies on trusted deployment/client configuration plus per-call redirect refusal, not a stronger claim about that helper.

- `tsc --noEmit`: passed.
