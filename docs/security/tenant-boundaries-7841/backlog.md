## Implementation sequencing decisions

- Ship a contract-complete metadata slice (B1+B2+B3), not a handler denial that
  breaks the real API producer while its replacement authority is still pending.
- Develop Door independently. Its readiness does not establish SSO or vault
  readiness. B4–B6 form the SSO security envelope; deploy only with the writer
  sanitation and recovery controls in place.
- Public registry mutation must not grant protected read or cross-tenant scopes.
  Do not give a shared agent role a global tenant just to keep a positive test green.
- Migrations are additive first. Existing domain organization IDs, ADP tenant IDs,
  callback URLs, provider subjects and ownership bindings are compatibility data.
  Preserve them unless the identity owner approves a separate reconciled move.
- Code comments requested by the story explain the verified-identity invariant
  at each repaired site; they are not substitutes for the enforcement tests.

## Backlog exclusions

No new security scanner, centralized authorization service, vault, identity-index
store, generic SSO secret provisioning system or automatic issue dispatch is
proposed. OIDC client credentials and live IdP operational readiness are existing
environment prerequisites; the current service's issuer-only details do not prove
a working live OIDC connection. Retain that uncertainty in S-12 rather than
claiming a stubbed provider test validates it. Unrelated modules in the inventory
receive no runtime changes under this story.
