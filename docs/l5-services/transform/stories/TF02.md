## The problem in plain terms

A project should reuse its existing repository and test information instead of requiring bespoke scripts. Missing information must be clear without granting access merely because it appears in a profile.

**The fix in one line:** Save scoped, versioned modernization settings and verify only the resources this project may use.

## Design

**Approved design:** Accepted 2026-10-27 at `f02387465846acbb9eda244f5815c0ab224ea87a`; [actual review](https://github.com/aws-e/adp/pull/9103#pullrequestreview-5669811881).

**Owned canonical sections:** [configuration and product handoff](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#configuration-and-product-handoff), [setup ownership and cleanup](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#setup-ownership-and-cleanup), [identity and isolation](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#identity-and-isolation).

**Starting point:** At main `388584bdd80a4a5ff142abe3234e7d1eac1cfd64`: ProductClient/internal Product APIs; L5 configuration/binding/setup stores; gateway `l5_integration.py` and delegated credential/snapshot routes. No direct Profile SQL.

- **Deliverables/entry points:** Extend existing configuration options/save/check/refresh/handoff and binding operation routes with the qualified Transform branch. Proposed `adapters/transform/` handles provider-specific setup. Advisory homes: L5 configuration/bindings/models and gateway integration.
- **Inputs/outputs:** Input: Profile/source revisions, authorized repository binding, explicit overrides, test_policy_ref, executor/connection refs, region and retention/budget policy. Output: immutable config revision/ETag, binding generation, readiness gaps and owned resource receipts. Save starts no paid work.
- **State/auth/recovery/compatibility:** Resolve current tenant/Product/project and exact selected account/role; pin source/goal/test policy. Preserve overrides on refresh. Adopted resources persist; ambiguous create reconciles saved intent, never creates again. Separate source write grants from advisory paths. Expose only capability-relevant gaps. Reuse shared SQL keys and compatible old readers.
- **Prerequisites:** TF01 contract/qualification and catalog mapping before provider-specific setup; current broker and eligible target needed for live checks only. Coordinator supplies private target, not public docs.

Paths are advisory, not write grants or node failure gates. Canonical sections own detailed schemas/limits; do not fork the architecture.

## Deployment

TF07 integrates wheel/gateway and additive payload/migration compatibility. Gateway main auto-deploy remains. Setup intent/operation/work rows recover owned create/cleanup; retire only after native readback and termination/absence evidence. Adopted assets are never deleted. Targets stay private. No new gate/allowance. Implementer owns repair through TF07 handoff; mocks cannot replace live evidence.
