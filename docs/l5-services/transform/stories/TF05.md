## The problem in plain terms

People and agents should see the same modernization settings, progress and evidence. Inspecting a patch must not silently authorize publishing or merging it.

**The fix in one line:** Use one scoped service contract in every client and keep repository publication a separate authorized action.

## Description

Own Product service tab, installed CLI/MCP parity and optional authorized SCM handoff; never provider execution inside a client.

## Design

**Approved design:** Accepted 2026-10-27 at `f02387465846acbb9eda244f5815c0ab224ea87a`; [actual review](https://github.com/aws-e/adp/pull/9103#pullrequestreview-5669811881).

**Owned canonical sections:** [api and client contract](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#api-and-client-contract), [identity and isolation](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#identity-and-isolation), [patch test and result provenance](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#patch-test-and-result-provenance).

**Starting point:** At main `388584bdd80a4a5ff142abe3234e7d1eac1cfd64`: Product workspace/services client, gateway CLI/tool transport, shared v1 client-operation matrix and Product-scoped L5 routes. Transform route/client branches are proposed, not existing commands.

- **Deliverables/entry points:** Add Transform service selection/config history/readiness, runs/freshness/cancel/reconcile, original diff/test/limitations views. Extend installed CLI and MCP operation schemas/envelopes. Proposed separate result-to-SCM handoff uses existing authorized SCM writer or reports unavailable.
- **Inputs/outputs:** Input: same typed config/run IDs, ETag, idempotency key and current actor scope. Output: same semantic data/http_status/etag in all clients. CLI admission success means accepted, not passed; wait distinguishes failed/unknown/local timeout. No raw credentials/provider URLs.
- **State/auth/recovery/compatibility:** Source/reference completeness never grants access. Preserve current-authority replay and artifact reads; no CLI/MCP bypass. PR action pins result digest/repo/base, requires separate SCM authority and durable handoff identity; lost ack reconciles branch/PR identity. No implicit push, merge or deploy; false readiness remains visible. Reuse shared SQL keys and compatible old readers.
- **Prerequisites:** TF01 typed contract and TF04 actual result routes; mocks permit early UI construction but not parity acceptance. SCM endpoint capability is unverified and must be qualified by this owner before enabling that optional action.

Paths are advisory, not write grants or node failure gates. Canonical sections own detailed schemas/limits; do not fork the architecture.

## Deployment

TF07 coordinates gateway/frontend normal main auto-deploy plus installed CLI/MCP artifacts at compatible versions. Handoff recovery retries only SCM publication, not Transform. Rollback disables new actions while retained results remain readable. Targets stay private. No new gate/allowance. Implementer owns repair through TF07 handoff; mocks cannot replace live evidence.
