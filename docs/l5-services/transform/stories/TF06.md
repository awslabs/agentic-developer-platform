A modernization result should remain useful to later authorized work. Publication retries and repeated schedule events must not create another paid transformation.

**Starting point:** At main `388584bdd80a4a5ff142abe3234e7d1eac1cfd64`: L5 event receipts/schedule receiver/work outbox and shared peer contribution contracts. Current schedule source selects Security; do not copy a scheduler. DevOps knowledge tables remain sibling-owned.

- **Deliverables/entry points:** Generalize registered service event selection; add Transform publication payload/receipt mapping to existing peer transport. If installed consumer/receipt adapter is missing, coordinate it explicitly with its owner. Proposed additive shared receipt fields require common-core review, not a Transform database.
- **Inputs/outputs:** Input: immutable result version/digest, current scope/visibility/retention and explicit trigger revision/goal/source policy. Output: consumer receipts, readback/reuse citations, deduplicated scheduled admission and denial evidence.
- **State/auth/recovery/compatibility:** SQL publication intent precedes send; key by result version/consumer/digest and reconcile lost ack. Never rerun paid work to fix publication. Recurrence off by default; freeze branch to exact source once per UTC occurrence and retain it on replay. Same admission/budget/source authority as manual. Revocation invalidates later reuse; no implicit Profile updates. Reuse shared SQL keys and compatible old readers.
- **Prerequisites:** TF03/04 finalized result contract and installed Context/Insights consumer ownership. Consumer availability is unverified; this implementer supplies exact entry-point/acknowledgement proof, with TF07 live integration.

Paths are advisory, not write grants or node failure gates. Canonical sections own detailed schemas/limits; do not fork the architecture.
