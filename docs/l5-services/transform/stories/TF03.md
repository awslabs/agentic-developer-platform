## The problem in plain terms

Long modernization work must survive request loss and worker restarts without starting a second paid operation. A timeout must not be mistaken for a provider failure or a confirmed stop.

**The fix in one line:** Submit once, retain native identity, and recover bounded observation of the same modernization run.

## Design

**Approved design:** Accepted 2026-10-27 at `f02387465846acbb9eda244f5815c0ab224ea87a`; [actual review](https://github.com/aws-e/adp/pull/9103#pullrequestreview-5669811881).

**Owned canonical sections:** [execution and recovery](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#execution-and-recovery), [executor and provider qualification](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#executor-and-provider-qualification), [sql entities and concurrency](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#sql-entities-and-concurrency).

**Starting point:** At main `388584bdd80a4a5ff142abe3234e7d1eac1cfd64`: L5 admission, work_store, dispatcher, execution/recovery workers, WorkerAttempt and AssessmentAdapter. Integrate DevOps admission PR #9081 rather than overwriting service discrimination.

- **Deliverables/entry points:** Proposed Transform adapter and non-blocking executor bridge under `modules/L5-services/src/l5_services/adapters/transform/`; extend shared stage attempt/work handling. Lambda only launches/observes bounded calls; finite provider CLI/test jobs run outside Lambda.
- **Inputs/outputs:** Input: admitted config/binding/source/goal/test-policy hash, current delegation/fence and frozen limits. Output: durable run, executor UID and native session refs, append-only observations and collectable artifacts. SQS receives opaque work ID/generation only.
- **State/auth/recovery/compatibility:** Commit SQL intent/attempt before every effect and publish immediately after commit. Stable stage identity across redelivery; stale owners cannot settle successors. Lost native acknowledgement reconciles original identity; no replacement submit. Keep native outcome/local cancellation separate; shared recovery still observes/collects late completion after local expiry under current authority and original limits. Credentials stay out of source/test jobs. Reuse shared SQL keys and compatible old readers.
- **Prerequisites:** TF01 must qualify current protocol, file-tool isolation and lost-ID readback; missing positive qualification disables paid submit. TF02 supplies ready scoped bindings. Executor owner exposes authorized non-blocking primitives without changing Task callers.

Paths are advisory, not write grants or node failure gates. Canonical sections own detailed schemas/limits; do not fork the architecture.

## Deployment

TF07 integrates shared worker/queue/recovery/executor release. Recovery uses existing bounded SQL due work and sweep, not a new scheduler. Rollback disables admission while keeping same-session reconcile/cleanup; no force-delete or budget reset. Targets stay private. No new gate/allowance. Implementer owns repair through TF07 handoff; mocks cannot replace live evidence.
