## The problem in plain terms

Modernization cannot be enabled safely from an old demonstration alone. Teams need to know which operations, isolation controls and recovery paths the selected provider actually supports.

**The fix in one line:** Publish a tested capability contract that enables only qualified modernization paths.

## Description

Own provider/executor qualification and the shared typed service contract, not runtime rollout.

**Owned canonical sections:** [executor and provider qualification](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#executor-and-provider-qualification), [api and client contract](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#api-and-client-contract), [sql entities and concurrency](https://github.com/aws-e/adp/blob/f02387465846acbb9eda244f5815c0ab224ea87a/docs/l5-services/transform/architecture.md#sql-entities-and-concurrency).

**Starting point:** At main `388584bdd80a4a5ff142abe3234e7d1eac1cfd64`: `run_input.py`, `adapters/protocol.py`, `docs/l5-services/contracts/v1/`; KubernetesValidationExecutor and the Task-only validation service. POC atx 3.19.0 JSON protocol is historical, not qualified current support.

- **Deliverables/entry points:** Add strict transform configuration/run/result/test branches and client registration without changing old Security/DevOps defaults. Proposed `docs/l5-services/transform/qualification.md` records exact CLI/image/protocol and supported limits. Resolve catalog IDs with coordinator/#8683. Coordinate #8932/#9081 common-core owners, not sibling architecture rewrites.
- **Inputs/outputs:** Input: current provider docs/binary digest, admitted source/test policy, selected connection and executor qualification. Output: versioned capability matrix, schemas/fixtures and explicit supported/unsupported recovery/tool-isolation cases. No account/repo/region constants.
- **State/auth/recovery/compatibility:** Select the existing credential-free Kubernetes validation executor; qualify a non-blocking L5 authority bridge, not a fabricated Task attempt. Existing checks stay at 120 seconds. Provider CLI runs in a separate finite trusted job with file-only tool mediation. Unknown submission never permits replacement paid work; unsupported cancel stays distinct from stop. Reuse shared SQL keys and compatible old readers.
- **Prerequisites:** Provider/auth/region and executor bridge unqualified; this implementer produces pinned qualification evidence before dependent live enablement. Module/feature mappings unresolved with coordinator before dispatch. Existing connection/budget authorization is required only for actual paid probes.

Paths are advisory, not write grants or node failure gates. Canonical sections own detailed schemas/limits; do not fork the architecture.
