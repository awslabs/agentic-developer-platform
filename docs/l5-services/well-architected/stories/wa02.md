## The problem in plain terms

Users can save selected architecture inputs and pillars, then explicitly create or adopt an Agent Profile without enabling unwanted resource discovery or deleting customer-owned setup.

**The fix in one line:** Configure and create or adopt source-only Agent Profile bindings.

## Design

**Approved design:** Accepted 2026-10-27 at `109fd8df85783557ea0efc4bba0ada53355f5c74`; [canonical slice][design]; [actual review](https://github.com/aws-e/adp/pull/9106#pullrequestreview-5669812097).

**Reuse:** Shared L5 SQL/workers, Product APIs/broker and contracts; canonical audit pins main/open-PR evidence. WA entry points are proposed.

**Contract:** Profile/source APIs supply authorized candidates; preserve overrides and conditional handoff on refresh. POST binding-operations selects create/link/check with pinned config and current connection. Persist stable setup token, exact native identity and ownership receipt separately from finite runs. Source-only requires aggregationConfiguration=[], qualified execution role, pillars and no unwanted native contexts/scheduled discovery. Readiness distinguishes eligibility, input and authority. Adopt never mutates/deletes foreign or customer-owned setup; serialize profile/source changes with active runs.

**Owned/advisory files:** Existing L5 configuration_population/readiness, api/configuration, api/bindings, models/setup and workers/bindings; proposed adapters/well_architected/binding.py; gateway l5_integration service authorization. Coordinate shared setup/broker owners #8684/#8686 and WA07.

**Dependencies:** #9098. **Prerequisites:** WA01 qualifies native source-only setup/trust and eligibility. Approved selected connection/role/store comes from WA07 under existing authority; no IAM/billing change authorized by this story filing. Catalog IDs remain WA01/coordinator-owned.
