## The problem in plain terms

Humans and agents can configure, check, run and read the same review through their preferred client; recurring work happens only when explicitly enabled and admitted.

**The fix in one line:** Expose shared UI CLI MCP reviews and opt-in scheduled admission.

## Design

**Approved design:** Accepted 2026-10-27 at `109fd8df85783557ea0efc4bba0ada53355f5c74`; [canonical slice][design]; [actual review](https://github.com/aws-e/adp/pull/9106#pullrequestreview-5669812097).

**Reuse:** Shared L5 SQL/workers, Product APIs/broker and contracts; canonical audit pins main/open-PR evidence. WA entry points are proposed.

**Contract:** Product Services tab and shared adp service/MCP matrix invoke one Product-scoped L5 API. Show inherited configuration, exact source/pillars/readiness, setup receipt, local/provider/freshness state, coverage/results and publication debt. Preserve shared conditional-write/error/JSON receipt semantics. Extend Security-only event service discrimination with scope-bound event/tick deduplication; enabled schedules use common manual admission and current budget/delegation. No native weekly discovery or browser federation copy.

**Owned/advisory files:** Existing gateway Product frontend, installed cli/adp packaging and MCP/tool catalog transport; shared contracts operation matrix and events/schedules receiver. Proposed Well-Architected service tab and shared adp service/MCP implementation; coordinate SA12–SA14 #8694/#8695/#8696 and WA07. No second public API or scheduler.

**Dependencies:** #9098, #9101, #9102. **Prerequisites:** WA01 typed client contracts plus WA04/WA05 run/results; shared client surfaces may still be unimplemented. WA07 supplies served frontend, installed CLI, authenticated MCP and deployed schedule fixture. Missing live eligibility blocks live journeys, not client error-state development.
