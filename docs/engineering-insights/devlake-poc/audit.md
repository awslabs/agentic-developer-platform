# Source, ownership and deployment audit

This audit supports the [canonical architecture](architecture.md). It is a **complete tracked-artifact enumeration and conservative build/deployment-entry discovery**, with focused source review of all affected boundaries, not a claim that every unrelated program was executed or semantically verified. The inventory work is delivered here, not deferred to a story. Live environments and custom DevLake builds were not exercised.

## Revisions and inventory method

ADP tree: `aeba89070ec685b41a4902a4441bfe47449e48ba`. Fetched default-branch revision `e048b35934e646e7f7f6b8ee950b87a021abe23f` has the same tracked tree (`git diff --stat` empty at inspection). These are source observations, not deployment receipts.

[audit_inventory.py](audit_inventory.py) enumerates `git ls-tree -r` at the pinned revisions, reads every tracked blob, preserves Git object hashes and assigns every path to a component or explicit exclusion. It does not copy source payloads, environment configuration or secrets into documentation. It records executable modes, every shell/PowerShell/Terraform/YAML file, workflow/action/container/package/build manifests, program main/shebangs and source matches for container/infra/artifact/database entry points. This deliberately includes test/config candidates rather than treating a keyword sample as the inventory. Resolved literal file references are recorded; generated/dynamic calls are a coverage limitation, not asserted resolved.

### Migration/data-store reconciliation

The migration graph, not numeric filename order, determines gateway schema history. Existing Profile foundation (`112`), scope guard (`113`), session (`115`), binding (`117`), operation lease (`118`), callbacks (`122`), flow binding (`124`) and source snapshots (`138`) are read together with all later/merge revisions in the inventory and current models. Existing catalog history is its own authority. `019_knowledge_assets` is a no-op tombstone, not an extant gateway table. Dynamic SQL operations are explicitly marked in the inventory; this audit does not execute migrations against a database.

No new DynamoDB, Secrets Manager convention or S3 bucket is proposed. Gateway metadata is relational; provider secrets stay in existing vault/connection services. The tracked infrastructure inventory includes all existing DynamoDB/S3/secret-related Terraform candidates, including identity and workload admission; unrelated module stores are explicit exclusions. Immutable evidence reuses Insights S3; cell databases are separate DBs on the existing instance. S12 new record names were checked against current gateway source and migrations; the live operator must still verify schema head and grants before an authorized migration.
