## Interfaces, data and authorization

Input: durably sealed S03 batch, read-only renewable IAM SQL connection, source binding/generation, S12 context, exact bytes/digests/times and full policy dependency graph. Output: immutable accepted record or restricted durable quarantine, original readback and resumable checkpoint. Source/record/relationship/mapping/schema versions remain distinct. Authority-resolve nested references before persistence; request paths and declared shared labels grant no access.

### Retained implementation requirements

- **Deliverables and entry points:** Proposed exporter/adapter under modules/insights/poc/devlake; pin mappings and reuse #8374 storage. Customization update: DevLake-side plugin/patch uses S09 images; ADP admission/evidence remains in Insights.
- **Inputs and configuration:** S03 batch and S12 authority: cell, canonical source/Project refs, binding generations, policy dependencies and mapping version. Preserve payload/digest/times; SQL exporter uses renewable read-only IAM. Retain only authorized bytes; unobserved history stays missing.
- **Outputs and behavior:** Atomic accepted observation or durable quarantine reason, authorized persisted readback and resumable checkpoint. Classify native, reviewed and heuristic relationships. Unlinked records remain in the common model without fabricated Stories; schema changes require an explicit version.
- **Compatibility and data:** Validate cell and nested reference/artifact policies before persistence; body IDs/paths grant no access. Unknown classification is restricted or rejected, including quarantine. Version policy envelope separately from fixed v1/v2. No gateway table reads or cross-realm fact multiplication.

The canonical architecture resolves placement, policy, publication and lifecycle details when the older implementation-contract summary is less specific. It does not relax any acceptance predicate. Common six-field identities, native provenance and current authorization remain mandatory.

## Fixtures, independent oracles and completion

Use colliding native IDs across tenants/Projects and private CI dependencies. Independently inspect persisted object versions/hashes against the native oracle. Crash before object commit, after commit before checkpoint, and after acknowledgement before reporting; replay compares the original immutable content, rejects conflicts and does not skip missing work. Current read denial must apply to retained historical bytes too.

Use the [shared verification controls](../verification.md#fixture-and-determinism-contract). Pin code, requirements, source revisions, clocks, routing/policy epochs and cleanup ownership. Authenticate through the real entry point; mocks may support pre-review tests but cannot substitute for required live proof. A plausible wrong result must fail the independent oracle, not merely match an implementation-generated fixture.

The delivery owner reports every acceptance ID as pass/fail/blocked/not-run with attempt, tested revision, expected/actual result and private evidence reference; the acceptance owner separately records the decision. Failed cleanup or missing required evidence is incomplete. [Architecture questions](../audit.md#unresolved-facts-and-coverage-limits) identify remaining readiness/fixture/ownership facts.
