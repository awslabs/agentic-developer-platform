## The problem in plain terms

ADP already has GitHub and Jira integrations. The POC must demonstrate useful
new integrations and prove that its optional connector service actually runs.

**The fix in one line:** Add SonarQube, Jenkins, Argo CD, GitLab, PagerDuty,
Linear and Slack through the Go service with reproducible provider acceptance.

### Implementation contract

Follow [the shared provider amendment](../provider-expansion.md) and
[planned files](../delivery-flow/planned-files.md#s14--provider-expansion).
Provider keys: `sonarqube`, `jenkins`, `argocd`, `gitlab`, `pagerduty`, `linear`,
`slack`. Scope kinds and upstream reuse are specified in the shared amendment.
Native cursors are internal continuations; the served layer binds them to current
ADP authority. Extend the extracted versioned
served request/context and durable cursor contract, registration/capability
schemas, UI and CLI together. Registered connection and current operation
authority select the endpoint. Provider credentials remain in ADP.

Master flag defaults off; collection remains separately optional. Connector-only
discovery has no collection grant/DB dependency. Reject disabled, foreign,
revoked, stale and unsupported work before provider access/admission. Preserve
Sonar project key, Jenkins folder/job path and Argo project/namespace/app identity.
Bound unpaginated Argo responses and report partial coverage. Go loss must fail
selected DevLake requests without native fallback. Preserve native integrations.

For explicit collection, reuse current cell/grant/IAM paths and the actual
[DevLake tool/domain tasks and models](../normalization-reuse.md). Do not create
a parallel generic `Fact` model or substitute ADP source-record metadata for
normalization. Preserve upstream original status/result and raw-record lineage;
prove Jenkins/GitLab in one normalized query. Slack remains tool-layer at the pin.
Retain only observed revision/artifact joins. Limit Slack to read-only selected test-channel data; no
posting, DMs or automatic bulk history import. Extend pilot
manifest/maps/results and both pilot/closure consumers for the seven-provider
supplement. Preserve original 44 criteria/history; no hand-edited engine context.

## Deployment

Use minimal declarative SonarQube/Jenkins/Argo CD manifests and seed/readback
steps within the existing campaign, with pinned images in one owned live namespace
when admitted. Reuse the campaign ledger/finalizer; do not build a new lab manager. Use an
owned GitLab test source and consented PagerDuty/Linear/Slack SaaS scopes. The
synthetic fixtures do not provision those services or establish live coverage. Do not use ambient
kubeconfig, public anonymous endpoints or host Docker socket in Jenkins. Keep
fixture bootstrap rights separate from broker read credentials. Existing AWS
target/plan and data-deletion gates remain; no deployment from this code node.

Use the existing connector/Insights build and coordinated qualify workflows.
Extend their current wrappers; no per-provider deployment workflows. Durable
manifest/ledger records partial creation, exact resource IDs and expiry; bounded
retry resumes the same run. Independent failure/expiry finalizer is qualified
before effects and deletes only owned resources. Coordinator owns post-merge
live source setup, evaluation and S08 cleanup handoff. Missing fixture/access
blocks that phase, not independent code fixes.
