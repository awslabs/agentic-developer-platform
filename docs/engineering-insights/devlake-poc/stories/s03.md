## Owned change and decisions

Correct the former collector location: proposed modules/insights/poc/devlake/cmd/collector-worker owns historical jobs, checkpoints, field mappings and evidence-oriented orchestration. Generic provider libraries are imported from connectors. Retain required upstream tasks/DAL/migrations in cell DBs; never enable Config UI or a duplicate credential database.

Review amendments R1/R2: all workspace writes lock/check the durable cell generation in their transaction; migration-owned guards fence stale workers. Drain tasks and atomically seal bounded native/normalized bytes, exact links, versions and policy into immutable batch items/manifest before reporting completion. Workers cannot modify sealed data; later generations change only workspace. S02 migrates the S09 manifest; runtime DDL becomes read-only migration_required checks. First/new-scope jobs require a matching receipt.

**Optional deployment amendment:** Require effective master and collection flags before scheduling/creation and at provider/persistence/export boundaries. Disabled collection creates no job. Revoke/fence generations during disable; retained sealed bytes survive, but enabling flags alone cannot resume old grants or backfill. See [verification and scope](../optional-deployment.md).

## Fixtures, independent oracles and completion

Use two tools with overlapping issue concepts and provider-specific PR populations. Independently enumerate native source records, query raw/tool/domain tables using authorized read roles and account for every exclusion. Compute PR count and creation-to-merge durations from native samples with fixed half-open UTC windows. Replay collisions, edits, revoked grants and 429 pages; no duplicate logical population, no private row or diagnostic in shared storage.

Use the [shared verification controls](../verification.md#fixture-and-determinism-contract). Pin code, requirements, source revisions, clocks, routing/policy epochs and cleanup ownership. Authenticate through the real entry point; mocks may support pre-review tests but cannot substitute for required live proof. A plausible wrong result must fail the independent oracle, not merely match an implementation-generated fixture.

The delivery owner reports every acceptance ID as pass/fail/blocked/not-run with attempt, tested revision, expected/actual result and private evidence reference; the acceptance owner separately records the decision. Failed cleanup or missing required evidence is incomplete. [Architecture questions](../audit.md#unresolved-facts-and-coverage-limits) identify remaining readiness/fixture/ownership facts.
