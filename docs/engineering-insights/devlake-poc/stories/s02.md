## Owned change and decisions

Proposed generic API runtime/infra under modules/connectors/devlake; cell worker/migration/exporter runtime and infra under modules/insights/poc/devlake, coordinated with #8375. Extend the pinned Go connection factory, not a static DB_URL wrapper. Record every owned resource and schema version in a private resumable ledger. Inventory exclusions in architecture §5.2 are release constraints.

Review amendments R2/R3: migration-only runner applies S09 schema manifest, including dynamic raw tables and generation/sealing guards, before job admission. Workers use read-only schema checks and DML; missing/incompatible schema returns migration_required without provider work. Extend S09 bootstrap finalizer with runtime/database handlers, validate scheduled/manual authority and register exact resource intents before provisioning. Compensation on partial failure/abort/expiry is independent of S07/S08 success; keep its ledger outside removable resources.

**Optional deployment amendment:** Implement the separately invoked connector infra root/state and optional Insights collection root/state in architecture §2.1. Propagate default-off flags consistently through launcher/workflow, gateway, broker and workloads. Prove fresh disabled installs create no add-on resources; connector-only needs no Insights/DB. Disable fences/drains operations and preserves data; explicit finalization removes only owned resources while flags remain off. S02 accepts a bounded real runtime/startup/gating harness before S10; actual provider/Profile proof belongs to S10/S11/S07, so no reverse acceptance dependency is introduced. See [verification and scope](../optional-deployment.md).

## Interfaces, data and authorization

S12 supplies registered cell/realm/workload destinations; S09 supplies checked digests. Operator supplies confirmed existing instance endpoint/resource/version, CA, SDK workload identity and connection budget. Provision distinct migrate/write/export users, exact rds-db:connect, SQL privileges, S3/KMS restrictions and verified TLS. APIs have no DB. Deny unsupported DB/TLS/password settings at startup. S02 baseline accepts a real bounded cell/IAM harness, not S03 collection or S10 discovery.

### Retained implementation requirements

- **Deliverables and entry points:** Proposed modules/connectors/devlake install/recovery from S12 registered cell routing; explicit API/worker identities and scoped DB/S3 permissions. Submit patches through S09; deploy digests. Preserve #8375 ownership of shared runtime changes.
- **Inputs and configuration:** Registered workload/TLS references; cell DB endpoint/resource/region/users, CA/limits and db_auth=iam. Broker resolves source credentials; no static AWS keys or DB passwords.
- **Outputs and behavior:** Stateless API has no DB pool. Inventory actual DB clients: migrations, worker/exporter and optional Grafana. Use IRSA/Pod Identity, refreshable SDK credentials and new-connection IAM tokens. No token logging or restart-based renewal.
- **Compatibility and data:** Separate migration/writer/export roles; exact rds-db:connect plus SQL grants. Revoke PUBLIC CONNECT on owned cell DBs; deny foreign roles/protected data. IAM is not a database-name or tenant filter. Scope S3/quarantine/results privileges; no cross-tenant ambient role. TLS verified; no password fallback.

The canonical architecture resolves placement, policy, publication and lifecycle details when the older implementation-contract summary is less specific. It does not relax any acceptance predicate. Common six-field identities, native provenance and current authorization remain mandatory.

## Fixtures, independent oracles and completion

For each deployed client force a new physical connection after token age exceeds 15 minutes, rotate underlying temporary AWS credentials and test expired/denied renewal. Wrong CA/hostname must fail. Probe another cell DB and protected legacy ADP objects with the cell role, and List/GetObjectVersion/Put/KMS outside its prefix. Compare independent SQL grants and shared DB load before/after. Open sessions or policy simulation alone cannot pass AC-04.

Use the [shared verification controls](../verification.md#fixture-and-determinism-contract). Pin code, requirements, source revisions, clocks, routing/policy epochs and cleanup ownership. Authenticate through the real entry point; mocks may support pre-review tests but cannot substitute for required live proof. A plausible wrong result must fail the independent oracle, not merely match an implementation-generated fixture.

The delivery owner reports every acceptance ID as pass/fail/blocked/not-run with attempt, tested revision, expected/actual result and private evidence reference; the acceptance owner separately records the decision. Failed cleanup or missing required evidence is incomplete. [Architecture questions](../audit.md#unresolved-facts-and-coverage-limits) identify remaining readiness/fixture/ownership facts.
