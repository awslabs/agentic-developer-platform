## Interfaces, data and authorization

Input: current viewer/tenant/Project, trusted dataset handle, full admitted policy closure, as-of/query/cursor. Output: complete authorized buffered response or existing concealed denial/incomplete status. Check before load and again immediately before release using fresh authority, not a stale DB transaction/cache. Version-bound cursor/cache binds viewer/tenant/Project/policy epoch/dataset/query. V1 Project pointer works only for proven compatible audience; otherwise explicit qualified v2 selector.

### Retained implementation requirements

- **Deliverables and entry points:** Extend results.py and gateway serving integration; proposed versioned internal dataset-policy descriptor. Reuse existing business_context API/CLI output where semantics remain compatible.
- **Inputs and configuration:** Authenticated viewer/tenant/Project, declared dataset/version, full S04/S12 policy dependencies, query/cursor. Caller paths/labels grant nothing; missing policy is not public.
- **Outputs and behavior:** Resolve current authority before selecting/loading and before releasing a bounded response. Deny affected complete result if any required dependency is inaccessible; no hidden-source IDs/counts or subtraction from aggregate totals. Preserve valid prior shared snapshot if an invalid publication is attempted.
- **Compatibility and data:** Bind cursors/cache to viewer/tenant/Project/policy epoch/dataset/query versions; reauthorize old versions and every page. Project-wide published.json is valid only for compatible single-realm scope. Version any multi-audience selector; do not reinterpret existing v1 schemas or bypass grants through artifacts/exports.

The canonical architecture resolves placement, policy, publication and lifecycle details when the older implementation-contract summary is less specific. It does not relax any acceptance predicate. Common six-field identities, native provenance and current authorization remain mandatory.

## Fixtures, independent oracles and completion

Use controlled S04 admitted shared/restricted fixtures through real authority/storage/reader and installed CLI before S06. Pause after loading bytes but before response release, revoke a real grant, then release barrier: zero bytes and no stale cursor result. Repeat historical/cache/page/export reads with foreign scope, missing descriptor and authority outage. A private input cannot affect a shared report’s totals/coverage/status; unauthorized whole-result denial must not expose private source IDs or counts.

Use the [shared verification controls](../verification.md#fixture-and-determinism-contract). Pin code, requirements, source revisions, clocks, routing/policy epochs and cleanup ownership. Authenticate through the real entry point; mocks may support pre-review tests but cannot substitute for required live proof. A plausible wrong result must fail the independent oracle, not merely match an implementation-generated fixture.

The delivery owner reports every acceptance ID as pass/fail/blocked/not-run with attempt, tested revision, expected/actual result and private evidence reference; the acceptance owner separately records the decision. Failed cleanup or missing required evidence is incomplete. [Architecture questions](../audit.md#unresolved-facts-and-coverage-limits) identify remaining readiness/fixture/ownership facts.
