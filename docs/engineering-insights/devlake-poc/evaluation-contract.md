Profile enrichment retains user selections and never requires historical collection. Separately authorized collection can later contribute versioned, policy-scoped evidence to Insights. ## Scope, policy and evidence

Proposed pilot ceilings pending owner approval: one primary registered Product/Project, two primary connections including a newly supported provider, three primary scopes, 30-day lookback, two concurrent collections and 14-day expiry. Interactive discovery: at most 100 records/page, five pages, 30 seconds/operation. Adversarial fixtures require at least two tenants, two Projects within one tenant, and shared/private evidence within a Project: at least four distinct cells, separately budgeted from the three primary scopes. Fixtures are not authority to access additional production sources. The source owner records included/excluded native records, revisions, relationship/timestamp oracles, auth mode and policy; absent native observations remain unavailable.

A cell is `(tenant_id, project_id, policy_realm_id)`, with an immutable sharing-policy descriptor (not a snapshot of reader membership). A fact is identified by `(tenant_id, project_id, source_connection_id, record_type, record_id, record_revision)`; cell, Product and policy realm are not extra fact identifiers. Preserve event, relationship, mapper, schema and dataset versions independently. Resolve the conjunction of current source-reader and execution-evidence policies across payloads, nested links, CI artifacts and cost dependencies. Reject unknown classification or use a separately authorized restricted cell; never let private evidence change shared results, denominators, freshness, pointers or public status. S12 authorizes grants/context with current generations; S13 rechecks readers at serving time. Missing authorization never means an empty or zero-valued metric.

## Optional modes and ownership

Only explicit case-insensitive `true` enables `FEATURE_DEVLAKE_CONNECTORS_ENABLED` or `DEVLAKE_COLLECTION_ENABLED`; both default off. The latter is effective only with the former. These are implementation requirements, not claims of working runtime behavior.

| Connector flag | Collection flag | Contract |
|---|---|---|
| off | off | Ordinary Profile/native tools work; no optional endpoints, images, IAM, DB, state outputs or health dependencies. |
| on | off | Connector-only Profile discovery; no Insights/cell DB dependency, collection jobs or implicit grant. |
| on | on | Independently opted-in collection only with current grants, cell policy, IAM/TLS and qualified Insights dependencies. |
| off | on | Invalid: reject activation, do not install resources or silently enable the master flag. |

S02 owns separate optional Terraform roots/state for `modules/connectors/devlake/infra/` and `modules/insights/poc/devlake/infra/`; S09 owns its artifact-publication ledger. Neither root adopts shared core/gateway state, cluster, PostgreSQL instance or Evidence Lake. Ordinary deployments do not invoke optional roots. Disabled gateway, direct Go and broker calls fail closed without provider traffic; S03 stops new jobs/exports and rejects late writes. Disabling fences and drains active generations, verifies *all* serving/worker/broker replicas and preserves Profile choices and governed evidence. Removal is a separate ledger-backed operation; switching a flag off never runs Terraform destroy or revives stale authority on re-enable. Existing native connectors remain unchanged.

## Storage, bounds and independent cleanup

Collection uses a separate cell DB on the *existing* PostgreSQL instance and renewable IAM/TLS authentication. Before provisioning, S02 and DB/access owners verify DB version/CA, network, roles, connection/storage headroom, IAM renewal under load and SQL migrations/grants; absent checks block cell setup, not connector-only work. Migrations run before first/new-scope jobs; worker is DML-only and returns `migration_required` before source access if schema/guards mismatch. S03 transactionally fences writers and durably seals exact bytes, links, versions and policy before completion; S04 exports only that immutable seal with read-only IAM and acknowledgement barriers, not mutable workspace rows.

Proposed staging maximum **per cell per admitted batch**: 100,000 rows and 100 MiB combined payload/link bytes. Reject or pause *before* exceeding either bound; never silently truncate, and preserve previously sealed batches. These values must be signed off against measured headroom before full-mode collection and revised explicitly if inadequate. The [measurement plan](measurement-plan.md) defines separate observation/cost ceilings.

S09 qualifies scheduler and manual artifact finalizer, protected exact-ownership ledger and authority **before artifact publication**. S02 qualifies runtime finalization **before cell provisioning**, independent of S07/S08 success. Proposed bounds pending operator verification: scheduler poll <=15 minutes, finalization-request acknowledgement <=30 minutes, disable admission fence/drain <=30 minutes and manual operator escalation within 60 minutes of failed authority/deletion; authorized pilot expiry is 14 days. Missed deadlines are incomplete and escalated, not automatically cleaned by TTL. Record intent before creation, durable per-resource attempts/receipts, independent absence and hold-preservation oracles and remaining cost. Failures, aborts and expiry trigger the same bounded finalizer even before S07. Never remove shared PostgreSQL, ADP connections/vault or Evidence Lake; retained storage may still cost money.
