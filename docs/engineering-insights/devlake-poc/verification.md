# Verification and acceptance procedure

**Delivery amendment:** [The POC flow](delivery-flow/README.md) uses code-only handoffs and one coordinated release campaign. Its [file plans](delivery-flow/planned-files.md) and [44-pair acceptance map](delivery-flow/acceptance-mapping.json) preserve all original criteria. Implementation checkpoints are not per-story deployment barriers.

This procedure supports the [canonical architecture](architecture.md), not an independent design. **Document validation is not live POC acceptance.** All future selectors in the 13 story designs remain planned; no cloud deployment, provider collection or production implementation is performed by this package.

## Reproduce the documentation checks

Working directory: repository root on `agent/issue-8887` (or the design PR revision). Prerequisites: Python 3, Git and the source commits retained in Git. Upstream inventory checking additionally needs a separate Apache DevLake checkout containing `6502e549f58eb40c40ccbcd39aab9bc8eea6616f`; `UPSTREAM_CHECKOUT` below is its local path, not an environment endpoint. ```bash

```bash
python3 docs/engineering-insights/devlake-poc/audit_inventory.py --check
python3 scripts/check-public-docs.py
git diff --check
```

For the complete upstream/source-link check, set `UPSTREAM_CHECKOUT` to the separate checkout path first:

```bash
python3 docs/engineering-insights/devlake-poc/audit_inventory.py --check --upstream-root "$UPSTREAM_CHECKOUT"
python3 docs/engineering-insights/devlake-poc/validate_design.py --upstream-root "$UPSTREAM_CHECKOUT"
```

Expected results: every pinned tracked path/hash/classification and migration parent matches; all local Markdown links/anchors and available pinned source paths/line bounds resolve; all 13 story AC/SCN sets and EC-01–EC-10 coverage remain; the native plus declared functional-capability dependency graph is acyclic. The checker reports external source links separately rather than pretending a local file check verified them. Its DAG includes the named shared capability prerequisites; external leaf capabilities are owner handoffs, not assertions that an entire release epic is complete.

Publication additionally prepares all 14 issue bodies outside the repository, runs the existing issue-authoring validator in **draft/planning** mode, checks the 8 KiB limit, preserves all criterion IDs and compares each amended AC/SCN table with its story design. The historical review and optional-deployment amendment records identify changed/new rows. Existing IDs remain; S02/S10/S11 add three pairs, and epic EC-01/02/08/09 now include the optional-mode requirement and references. This is intentional: registered scope and owners remain unresolved, so a ready implementation-issue claim would be false. The requesting owner authorized merging the corrected design; execution readiness remains separately assessed. Optional `validate_design.py --issue-dir PATH` checks those prepared `.md` bodies; the supplied directory must contain `8887.md` and all 13 child numbers. GitHub readback then confirms exact body equality, immutable design links, unchanged native hierarchy/dependencies and unchanged issue state. No labels, flow registrations, gates or dispatches are added.

Existing bounded source checks, from repository root:

## S01 SCN-01: independent evaluation-contract review

**State: planned manual review; no named source, operator or acceptance owner has signed this contract.** The lead schedules this review before declaring S01 AC-01 ready for dependent resource work. Review the [contract](evaluation-contract.md), [machine-readable bounds](pilot-contract.json), [public readiness matrix](readiness.md), [canonical architecture](architecture.md) pinned at `a9c014f2537bf7956970e8484ce44f9b613104c8` and the *privately stored* owner/fixture manifest; a document-only check cannot substitute for owner interviews. Pin the actual reviewed revision and private-manifest revision in the decision receipt. Never copy source identities or private evidence into the public record.

1. **Check who and what is authorized.** The lead obtains independent acknowledgements from named build, connector, Profile, scope, source, Insights, DB/access, verification, operator and acceptance owners. The scope owner independently reads the Product/Project/catalog registration, two connection bindings and grants. Record exact private refs, authorizing actor, source-reader policy/realm and 14-day expiry; no fabricated IDs or assumed approvals. If any is unknown, mark the corresponding [readiness row](readiness.md) blocked with owner/action and affected stage, not failed for the entire offline package.
2. **Compare boundaries and modes.** An independent reviewer compares all four flag combinations against the pinned architecture: both absent/off leave ordinary ADP/Profile and native integrations working; connector-only saves Profile without Insights DB, jobs or grants; both on require additional current collection authority; collection-only is rejected. Compare separate connector/Insights infrastructure roots and state, ADP credential ownership, no static-token DSNs or gateway-table reads, S12 cell/grant authority and S13 current-read enforcement. Treat any missing bypass, mode or incompatible ownership rule as a review failure, not implicit scope expansion.
3. **Check bounded policy and staging.** Independently compare the two-tool/three-scope/30-day/two-concurrent/14-day proposal, interactive discovery 100/page × five pages × 30 seconds, at least four adversarial cells, per-cell batch ceilings of 100,000 rows and 100 MiB, and protected private/shared realm dependencies. Include same-tenant Project and foreign-tenant colliding native IDs; an unowned or unlabeled fixture cannot support an isolation pass. DB/access owner measures IAM renewal, TLS CA and headroom before approving the staging ceiling; unknown measurements block cell provisioning but not connector-only work.
4. **Check disable and finalizer before any resource.** Operator and S09 independently demonstrate scheduler/manual artifact-finalization authority and an external protected ledger before image publication; S02 demonstrates runtime finalization before cell provisioning. Approve or revise the proposed poll <=15m, request acknowledgement <=30m, disable fence/drain <=30m and escalation <=60m deadlines. Deny cleanup authority in the controlled review: expected result is no resource creation or a blocked/escalated cleanup, never a successful TTL-based cleanup. Inspect explicit holds, exact ownership and shared-state preservation. This step describes future operational proof; do not provision resources merely for this document review.
5. **Record an independently attributed decision.** Compare the retained #7295 W2/gateway-read gap, #8374/#8375/#8373 handoffs and V13 deferral with the lead's stage matrix. Record AC-01 and SCN-01 as pass, fail, blocked or not-run with requirements/source/contract/manifest revisions, reviewer identity in the private record, attempt, expected/actual observations, approvals, outstanding row/owner/action and any cleanup result. A missing owner, native fixture, IAM/headroom observation or independent review cannot be turned into pass by public-doc checks or a PR merge. The acceptance owner decides readiness separately from the developer's documentation check.

4. **Bound and close the attempt.** Use at most two primary connections, three primary scopes, 100 records/page, five pages, a 30-second interactive operation, 30-day lookback and two concurrent historical jobs *only if separately authorized*. Record AC-02/SCN-02 pass, fail, blocked or not-run with source/mapper/contract revision, attempt, expected/actual native observations, private evidence and cleanup. ## S01 SCN-03: independent measurement-plan review

**State: planned manual acceptance-owner review; no 48-hour source campaign or billed-cost observation has run.** Before measurements, the acceptance owner and an independent verifier inspect [measurement plan revision 1](measurement-plan.md), [pilot bounds](pilot-contract.json), [source map](source-field-map.json), and the private approved scope/fixture/retention and clock-skew manifest. Pin the reviewed contract, code, map, source, schema, target and policy revisions. A synthetic offline calculation checks the rule, not actual freshness or financial cost.

1. **Freeze the oracle before collection.** The source owner records exactly 20 intended native updates across *both* approved providers, with first-to-last source-event timestamps spanning at least 48 hours, expected native IDs/revisions/links, policy/reader, exclusions and a separately verified UTC clock. Capture native responses and hashes independently of the connector. Approval must precede provider work; record any unavailable native timestamp as unavailable freshness rather than replacing it with collection or report time. Include selected Profile resource facts and no inferred work or cost from points or PR count.
2. **Check the sample and denominator.** The verifier reconciles each of the 20 intended updates to its native fixture, source observation, sealed generation, admission, qualified publication and first authorized served API/CLI or Profile readback, retaining intervening timestamps. Compute nonnegative per-update source-to-result lags after *approved measured* clock-skew correction. Sort exactly 20 lags and use item 19 (nearest-rank p95); <=15 minutes only passes if every selected update is accounted for over >=48 hours. For an illustrative **synthetic** fixture of 19 lags of 14 minutes and one of 30 minutes, p95 is 14 minutes; 18 of 14 plus one of 16 and one of 30 gives p95 of 16 minutes and fails. A missing twentieth update, missing native timestamp or unreadable authorized result is incomplete/unavailable, never a smaller denominator or a passing 19-item sample.
3. **Reconcile coverage and measure cost separately.** For each provider/cell/realm compare *source-owner-enumerated* permitted native records and relationships at the frozen cutoff to exact sealed hashes, immutable admitted versions and served result counts. Show excluded, missing, conflicting and restricted evidence separately. Reject duplicated updates and any private/foreign record changing shared totals, denominator, coverage, freshness or pointer. An empty/unavailable independent oracle makes the coverage ratio unavailable. Separately compare observed per-job CPU/memory, concurrency, per-cell storage, provider/API quota, renewable IAM/TLS and itemized incremental charges to the operator-approved pilot ceilings, including idle/retained cost and estimated versus billed basis. Unknown cost/attribution is unavailable, never USD 0 or an approved-budget pass.
4. **Bound the run and record the decision.** No more than two primary connections, three scopes, two concurrent collections, 30-day lookback and the 14-day expiry; stop before 100,000 staging rows/100 MiB per cell/batch, proposed 2 vCPU/4 GiB per job, 10 GiB per cell or total USD 100 are exceeded. The DB/operator and acceptance owners must first approve or revise those *proposed* limits against measured headroom and charges. Poll the real served route only within an approved bounded observation deadline; freeze clocks, pagination, source revisions and identities before retrying. At expiry/abort/rejection invoke the qualified ledger finalizer, independently check exact owned-resource absence, holds, retained evidence and residual cost; do not create validation infrastructure for this review. Record AC-03/SCN-03 attempt, revisions, numerator/denominator, p95, expected/actual independent observations, missing inputs, pass/fail/blocked/unavailable/not-run, private evidence ref and cleanup. The acceptance owner signs the decision independently; a document test or merged PR cannot satisfy it.

## Isolation, failure and lifecycle proof

Every boundary needs both authorized positive and unauthorized negative cases: discovery, broker delegation, raw/diagnostics, DB role/schema/sequence/default grants, S3 list/read/version/write, KMS decrypt/data-key context, immutable admission/nested artifacts, projections/quality reports, publication pointers, API/CLI/cache/pages/history/download/export. Use tenant B, same-tenant Project A2, private A1 evidence, colliding IDs, concurrent calls, body-forged roles/paths/cells and authority outage. Independently inspect that unauthorized effects/bytes do not exist; a 403 alone does not prove no earlier write.

For final read revocation, block after object bytes are buffered and before the final authority decision; commit source/evidence/Project revocation through the normal authority route, then release the barrier. Assert no body bytes and no usable stale cursor, and verify a separately authorized reader still works. Final authorization is the release linearization point; already sent data cannot be recalled. Repeat with retained old datasets, caches, exports and invalid policy epochs.

For IAM renewal, instrument connection attempts without logging tokens. Expire the token age, close the pool’s physical connection and reconnect with the same running process; then refresh underlying temporary AWS credentials. Repeat for writer, exporter, migration tool and gateway migration/runtime clients selected in the POC. Test wrong CA/hostname, foreign role/database/object, expired grant and reconnect after failure. No stored DB-password fallback, ambient-role substitute or Pod restart proof.

Crash injection covers submission before acknowledgement, before/after durable seal commit, between export pages, object commit before checkpoint, acknowledgement before reporting, pending dataset before pointer, and pointer update before independent receipt. Recovery replays the durable journal and compares canonical identity/hash; no duplicates, silent gap advancement or false complete pointer. Restricted invalid publication cannot change any shared data, coverage, freshness or visible status.

Cleanup starts with verified scheduled/manual authority and a protected ownership/retention ledger before resource creation, not a namespace deletion. It covers raw/tool/domain and sealed batch state, roles/grants/jobs/volumes, object versions/delete markers/old manifests, datasets/exports/quarantine/cache/spill/logs, source fixtures, images and backup holds. Inject one deletion failure and verify resume plus independent absence/retention. Preserve shared PostgreSQL, ADP DBs/other tenants, connections/vault and required retained evidence. Physical shared-backup expiry is separately owned and reported; revoked readers remain denied.

- **R1 / S03 SCN-01/03, S04 SCN-01/03, S07 SCN-02:** independently capture B1 native bytes, links and digests before collection.
