# Shared agent launch configuration

Agent model settings belong to the launch service in `src/agentauth/launch_configuration.py`. The delivery engine supplies the verified initiating human, tenant, and persona; it does not implement model precedence or attach model fields itself. Individual GitHub/chat producers reach the same resolver through the authenticated persona-model endpoint. The former admin module remains an import compatibility shim.

Resolution happens before consuming a story attempt and before the envelope is sealed for protected execution. Saved preference validation failures leave the story ready, without publishing a run using the worker default. Explicit individual-run choices and configured system defaults retain their existing precedence. The persona mapping feature flag remains owned by the launch layer; this change does not alter organisational settings, budgets, or model access policy.

Planning-agent publication now resolves settings for protected as well as ordinary launches, and passes the configured envelope into authority provisioning. Previously the protected path skipped the saved preference.

## Claude SDK update

Both Claude Agent SDK packages are pinned to npm latest `0.3.283` (checked 2026-09-27), replacing `0.3.220`. Runtime contract revisions, webhook catalogue metadata, and SDK/gateway request-shape manifests are updated together. The manifests were regenerated by invoking the installed SDK twice per model against a loopback fake Bedrock upstream, confirming stable fingerprints for all 12 models including `global.anthropic.claude-opus-5-5`. This is SDK request-construction evidence, not provider-invocation evidence. Old provider evidence remains keyed to its old SDK revision and is not relabelled as new evidence.

The upgrade does not change the user's selected model to Opus 5.5 automatically. Live provider access and successful story completion require separate runtime verification.
