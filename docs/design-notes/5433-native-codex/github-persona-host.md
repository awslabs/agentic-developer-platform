# Shared Codex GitHub persona host

The GitHub adapter uses the existing shared Codex SDK harness and canonical persona/rule catalogue for architect, product, PM and intent refinement. Their exact mentions are `@agent-codex-architect`, `@agent-codex-product`, `@agent-codex-pm` and `@agent-codex-intent-refinement`. Native developer/reviewer and Claude retain their existing commands and implementation.

Registration is separate from enablement. The gateway requires `ADP_CODEX_GITHUB_PERSONAS` to list the exact permitted names. Its generated packaged catalogue comes from `codex-harness/scripts/github-catalogue.mjs`; CI checks it against the canonical definitions and rule digests. `ADP_CODEX_PERSONA_CATALOG_FILE` can select an operator-managed catalogue. Neither a definition nor an issue can grant capabilities. Enablement requires a matching worker image, committed Codex model policy, signed controls and independently qualified invocation support.

The gateway verifies the existing run credential and workload identity, then signs the resolved model and frozen persona context together. Model precedence remains the shared resolver's explicit selection, user mapping, persona default and SDK class default. New routes require a signed proposed decision even when the existing class posture is report-only; they have no legacy model fallback. Existing SDK class posture and launch behavior are unchanged.

The protected context pins the persona definition, rule/skill references, GitHub repository ID, issue and budgets. The host checks GitHub's current repository ID and reads only the checked-out commit through bounded `git show`/`ls-tree` tools when repository reading is admitted. It runs the SDK in the shared isolated environment without GitHub or AWS credentials, shell access or native mutation tools.

Pause and cancellation use the existing signed control runtime and Codex adapter. Amendments continue the same SDK thread. Model, tool and final publication effects are reserved and settled in the protected authority table. An uncertain effect prevents automatic replay. Replacement worker attempts currently require reconciliation instead of restarting the task and repeating work. Final publication is a GitHub comment, with invocation-bound metadata; worker finalization does not auto-commit or open a PR.

Local qualification includes actual pinned SDK execution from a relocated image layout with fixture inference, signed HTTP context and workload rejection tests, repository path/commit isolation, controls, durable effect fencing and worker report finalization. This evidence establishes implementation boundaries, not live rollout or full persona-story acceptance. Architect story creation, PM scheduling, operations credentials/mutations, AI-DLC phase/approval artifacts, native shared-rule compatibility and broader lifecycle qualification remain owned by #6676 and #6195–#6207. Those stories must not close based solely on these report fixtures.
