# Native Codex model invocability probes

Native developer and reviewer use separate SDK-generated request hashes. They remain outside `TASK_PERSONAS`. A developer request includes native tool schemas; reviewer additionally uses the actual `reviewOutputSchema`. Both use the pinned SDK, high reasoning effort and the native worker permission mode in an empty temporary workspace. Capture runs with a fresh home and an explicit environment containing no provider or worker credentials. Its loopback server rejects WebSocket negotiation, captures one HTTP request, returns 403 and aborts the SDK. No model output reaches the SDK and no model-selected tool can run.

`codex-reviewer/scripts/generate-native-probe-manifest.mjs` captures every supported model/persona twice and refuses non-reproducible hashes. It writes identical manifests for the native package, probe worker and gateway. Normalization pins only probe-local message/session identifiers, timestamps, equivalent UTC timezone spellings (`Etc/UTC`, `/UTC`, `UTC`) and temporary roots in SDK context. Other timezones are not normalized. Other metadata, instructions, tools, permissions, reasoning and structured output stay in the digest. The provider probe deliberately uses non-streaming output capped at 512 tokens, with storage disabled. This is a bounded SDK-generated request compatibility check, not a receipt for a completed native agent lifecycle. Changes to semantic fields invalidate its hash.

The worker selects a native profile with `ADP_NATIVE_PROBE_PERSONA`, mutually exclusive with `ADP_TASK_PROBE_PERSONA`, and still requires `ADP_PERSONA_MODEL_PROBE_ENABLED=true`. The existing gateway probe configuration, model allowlist, registered platform destination, cycle budget, dedicated probe identity and durable claim/start/complete ledger remain required. A positive operator-configured reservation must cover the bounded request (at most 65,536 serialized input bytes and 512 output tokens); this code does not discover current prices or change those budgets.

Before start releases destination credentials, the worker recaptures the request from its own installed SDK and compares it with both manifests and the admitted hash. Only one provider request is made. Missing receipts, transport uncertainty, incomplete output and tool calls produce no successful proof. Developer requires the exact OK response; reviewer requires the structured empty approve verdict. Provider output is never fed back to the capture SDK, so the probe cannot execute native tools. An uncertain start is not retried.

Gateway promotion and protected selection require fresh evidence for the selected native persona, model, SDK revision, exact request digest and registered destination. Reviewer evidence cannot promote developer, and Task evidence cannot promote either. Class-wide Codex defaults still have no shared native contract. This implementation does not activate a default, change enforcement posture, enable report personas or establish live GitHub qualification. Operations, AI-DLC and other executable persona contracts are separate work.
