# Private CI evidence

The ARC runner workflows retain test evidence in an account-local S3 bucket instead of GitHub's artifact storage. Tests still run on `arc-runner-org`. Failed uploads fail required evidence steps; this does not waive tests or evidence gates.

Each upload retains the original files in a tar.gz archive and a JSON manifest with per-file hashes, checked-out commit, workflow commit, repository, run, attempt, job, and the S3 object version. The Actions step summary and log contain the private manifest URI, version, and checksum. No public URLs or presigned links are emitted. Control evaluation still consumes the original `checked-out-revision-<job>` JSON file; unpack the archive into the evaluator's existing evidence bundle without editing that file.

The bucket blocks public access and ACLs, requires TLS and conditional `If-None-Match: *` writes, encrypts objects, and retains versions. Retention classes are 7, 14, and 90 days. The runner receives only `s3:PutObject` and `s3:GetObject` under this bucket's `artifacts/` prefix, alongside its existing CodeBuild source prefix. It cannot list or delete objects, modify the bucket, or access Terraform state or product artifacts. Object checksums and version IDs must be checked against the producing job's receipt; an unverified object listing is not provenance.

## Provisioning

Use the approved deployment account and identity. This isolated Terraform root only manages the CI bucket; it does not apply the factory or alter workloads. For the existing dev installation:

```sh
terraform -chdir=platform/ci-evidence-infra init \
  -backend-config=bucket=adp-terraform-state-879318057152 \
  -backend-config=key=dev/ci-evidence/terraform.tfstate \
  -backend-config=region=us-east-1 -backend-config=use_lockfile=true
terraform -chdir=platform/ci-evidence-infra plan \
  -var=account_id=879318057152 -out=/private/path/ci-evidence.tfplan
# Inspect the saved plan before applying that exact file.
terraform -chdir=platform/ci-evidence-infra apply /private/path/ci-evidence.tfplan
```

The canonical runner grant and boundary are generated by `modules/agent-factory/infra/modules/runner-runtime-policy`. Existing installations can use `platform/scripts/ci-evidence-runner-policy.py` to prepare and apply a snapshot-guarded update limited to the new object prefix. It preserves every unrelated grant and deny and records the previous policy versions for rollback. The bucket must be provisioned first. Never use a deployment role inside a pull-request job.

## Downloading evidence

Read the manifest URI and version from the producing job summary. Use your existing authorized operator identity to download that exact version, verify its SHA-256 against the job receipt, and then download the archive at the version recorded in the manifest. Verify the archive SHA-256 before unpacking it. Files remain private; access is governed by IAM.

Manual agent-control runs can test source revisions older than the uploader. Those jobs fetch the uploader from `GITHUB_WORKFLOW_SHA` without changing the checked-out source revision or its checkout-evidence record.
