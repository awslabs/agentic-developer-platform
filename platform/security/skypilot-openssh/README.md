# SkyPilot OpenSSH source backport

This emergency overlay reuses the authenticated Debian OpenSSH source build and
reviewed client-lifetime patch already shipped for DeepWiki. It installs the
coordinated client, server and SFTP packages at the truthful downstream version
`1:10.0p1-7+deb13u4+adp.security.1`. The server's exact client dependency stays
satisfied. No client/server capability is removed; the patch scope is only
CVE-2026-60002. Other OpenSSH advisories remain open.

Build from the repository root:

```sh
docker build -f platform/security/skypilot-openssh/Dockerfile \
  -t adp-skypilot:ssh-security .
python3 platform/security/skypilot-openssh/verify_container.py adp-skypilot:ssh-security
```

The fixed base is the published rsync/curl candidate. Ordinary component builds
do not automatically apply this overlay. The build retains Debian package
integration and configuration, and removes any host keys newly generated by
package postinst within the same layer. Runtime host-key provisioning remains
with the existing deployment configuration.

The image also supplies a passwd/group entry for the existing Kubernetes UID/GID
1000. Python's USER-based name lookup allowed the previous image to start, but
native SSH requires getpwuid(1000) to resolve. This preserves the deployed numeric
identity and enables native SSH at that identity.

The fixture exercises actual installed client AND server binaries with fresh
synthetic keys, private loopback and no exposed ports: key formats/passphrases,
ordinary rekey, Git clone/fetch/push, SCP/SFTP, wrong-host and invalid-config
refusals. It disposes of its containers and volume. The server fixture is root,
the application client is UID1000; no operator credentials are mounted.
The packaged SkyPilot API health/restart/status/task-parser test also passed.

`review-candidate.py SCAN_DIRECTORY OUTPUT_JSON` verifies the candidate source
lock, versions and seven installed binary hashes against the authenticated build
packages. It binds the three source-package scanner occurrences to the reviewed
backport and combines curl/rsync reviews rebound to the same digest. Raw scanner
results are untouched. This establishes a reviewed candidate, not live closure;
real Postgres/provisioning and controlled cluster acceptance remain required.
