## Implementation plan — PMM-02 (#5419), five-item correction at `cdecaf20`

### My understanding of the task

PR #5472 implements the persona-model preference store, service-principal identity lifecycle, and authenticated API. The latest requested-changes review identifies five remaining merge blockers at the current head. Each is a correctness defect in the delivered surface, not a missing feature.

**1. Cognito M2M callers carry `sub` instead of `client_id`.** `_parse_claims()` in `cognito_jwt.py` always sets `username = payload.get("username", payload["sub"])`, so for client_credentials tokens (which have no `username` key in the payload) `claims.username` is truthy (it gets `sub`). The branch in `_cognito_claims_to_context` that would use `client_id` — `if account_type == "service" and not claims.username` — is therefore unreachable. `user_id` stays as `sub`, but the PMM dependency resolves `cognito_m2m` aliases using `user_id`, so it looks for `sub` instead of the registered `client_id`. A registered `(org, cognito_m2m, client_id)` alias never matches.

**2. Tests bypass the real auth paths.** The HTTP fixture overrides both `get_current_user` and `get_persona_model_current_user`, so none of the existing tests exercise the upstream SigV4/Agent Registry or Cognito JWT construction. The cross-namespace negatives call `resolve_by_exact_source` directly, not through the dependency chain.

**3. Pending additions run before the savepoint.** In `register_service_principal` and `link_alias`, `db.add()` is called before `async with db.begin_nested()`. SQLAlchemy can auto-flush pending state when entering the savepoint, and a uniqueness violation at that point occurs outside the savepoint, poisoning the outer transaction. A losing registration also orphans its principal row.

**4. Admin alias lookup is not tenant-scoped.** `routes.py` lines 168-173 select the source alias by `canonical_id` and `is_active` only, without an `org_id` predicate.

**5. Manageable-principal provenance is untruthful.** `list_manageable_service_principals` maps `eventbridge` and `github_actions` aliases to the fallback label `"service-accounts"` instead of reporting their actual source.

### How I plan to implement it

**Step 1 — Fix Cognito M2M `client_id` in the construction path.** In `_cognito_claims_to_context`, change the service-account branch: when `account_type == "service"`, always use `claims.client_id` as `user_id` if `client_id` is present. Refuse with 401 when `account_type == "service"` but `client_id` is empty (incoherent token shape). Also reject when `account_type == "service"` and `claims.client_id == claims.sub` is not verified — the current code works by accident because `sub` happens to differ from `client_id` in real Cognito client_credentials tokens. The key change: `_parse_claims` should not pre-fill `username` with `sub` for client_credentials tokens that genuinely lack a `username` field.

**Step 2 — Move pending additions inside the savepoint.** In `register_service_principal`, wrap `db.add(principal)`, `db.add(alias)` and `await db.flush()` inside `async with db.begin_nested():` so both the principal and alias are created atomically within the savepoint. A losing registration's principal is rolled back with the alias — no orphan. Same for `link_alias`: move `db.add(alias)` inside the nested block.

**Step 3 — Add tenant predicate to admin alias lookup.** At routes.py:168, add `ServicePrincipalAlias.org_id == current_user.org_id` to the query. Add a negative test proving a cross-tenant alias does not leak into the admin path.

**Step 4 — Fix manageable-principal source labels.** Widen the `source_map` in `list_manageable_service_principals` to include all five approved sources with truthful labels. Widen `ManageableServicePrincipal.source` in schemas.py to accept the full vocabulary. Remove the fallback that mislabels sources.

**Step 5 — Real upstream auth tests.** Add a test class that does NOT override `get_current_user` or `get_persona_model_current_user`. For the Agent Registry/SigV4 path: mock `get_settings().trust_apigw_headers`, mock the agent registry to return a matching entry, send `X-Caller-Identity` header, and verify canonical resolution through the real dependency chain. For Cognito M2M: mock the JWT validator to return a service token where `client_id != sub`, and verify `user_id` carries `client_id` and `alias_source` is `cognito_m2m`. Add the decisive cross-namespace negative through these real paths.

**Step 6 — Full suite and evidence.** Run ruff, format, and the full gateway test suite. Post SHA-bound AC evidence.
