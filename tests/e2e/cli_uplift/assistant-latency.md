# E49 assistant latency (opt-in)

The assistant suite includes E49, but preflight blocks its expensive turns unless private run configuration explicitly sets `assistant_latency.enabled` to `true`. Running the offline tests does not connect to a target or provision a validation service. A live run requires the usual approved evaluator target and budget, and the separate #6937 operator must settle which captured baseline is acceptable; merely including baseline samples does not approve them.

Configure each measured mode in a separate authorized `eval-cli-uplift.yml` run with `suites=assistant`. Supply `assistant_latency` in protected run configuration, not in a committed example. The driver accepts `baseline`, `cold`, `image-warm`, `node-warm` or `persistent` as `mode`. Supply exactly 30 distinct scripted `prompts` with `id` and `text`; the driver sends one first turn and one follow-up in the same owned session for each prompt. Baseline capture runs with `mode=baseline` and no `baseline_samples`, so its verdict is BLOCKED while it records raw samples. Only after an approved baseline decision should a candidate run receive that baseline's JSONL samples as `baseline_samples`; for `transport=real_model` also provide `baseline_decision_ref` naming that reviewed decision, otherwise the candidate blocks before dispatch. mismatch in model/version, region, client path, prompt text hashes, output class, concurrency, fixture or transport blocks comparison.

The required inputs are `model`, `model_version`, `fixture_revision`, `transport`, `concurrency` (currently exactly 1), `output_size_class`, `approved_budget_usd`, `max_turn_usd`, `node_hourly_usd`, `max_idle_nodes` (0–3) and `max_measurement_seconds` (up to 3600). The spending guard reserves the maximum idle-node charge and one configured per-turn maximum before sending; it stops before a further turn if the configured limit would be crossed. Real-model charges require a correlated response usage receipt with input/output token counts and `estimated_usd`. When usage is missing, the driver stops after that turn and blocks the cost verdict rather than pricing it as zero. `transport` separates deterministic and real-model measurements.

For a capacity-cost verdict, provide `capacity_observation` with the selected `mode`, a verified target `revision`, `window_seconds`, and `idle_node_seconds` observed by the authorized operator. The report labels this an operator-supplied observation; the driver cannot independently inspect cluster idle resources. Without it the cost verdict is BLOCKED. Approved budget and observed idle capacity must be verified in the live #6937 run. Warming is operator-controlled outside this driver: it does not patch Kubernetes or remove capacity it did not create. For persistent sessions it reads the prior owner-scoped mode, selects persistent, and restores and verifies the prior value even if sampling fails. A restore failure marks the run non-clean and names the setting. A private 0600 journal is written before each non-idempotent WebSocket send or mode change; a repeated or interrupted run blocks for operator reconciliation instead of automatically resubmitting a billed turn.

`report.json` contains each criterion's status, counts, p50/p95, variability, cost and the design revision; `assistant-latency-samples.jsonl` contains one sanitized row per attempted turn, including timeouts, with the harness and deployed revisions. The offline artifact writer creates an empty JSONL file when E49 was not run. The workflow retains only these sanitized artifacts and `results.xml`; it does not publish private runner state. A completed implementation PR is not the #6937 live verdict.

To reproduce the offline checks after installing the workflow's pytest dependencies (`pytest`, `pytest-timeout`, `pytest-socket`, `pyyaml` and `boto3`):

```bash
python -m pytest tests/unit/test_cli_assistant_harness.py -q --disable-socket --allow-unix-socket
```
