# Maintained cryptography runtime wheel

The authenticated cryptography 46.0.7 source's maturin `include` entries put
`docs/`, `tests/`, and two generic RST files into its runtime wheel. The existing
image consequently has ambiguous top-level ownership and unhashed documentation
bytecode in cryptography's RECORD. This recipe makes those four include entries
sdist-only; all public runtime Python source and native functionality remain.

`source-lock.json` pins the official PyPI archive, two upstream production-only
maintenance patches and their resulting Rust source hashes. The committed
patches use zero-context encoding to avoid whitespace-only context lines; the
upstream authenticated patch identities are retained separately. No upstream
vulnerability or vendor regression suite is invoked.

The builder compiles a fresh native extension using the source's Cargo.lock and
locked maturin dependencies. Only this throwaway builder aligns libc to Debian's
matching development headers; no builder system library enters the runtime.
OpenSSL headers use the same 3.5.7 package version as the runtime shared library.
The build exports the wheel, its SHA256, all prepared source hashes, installed
build package versions, Python dependency versions, and Rust/Cargo versions.

Build from this directory, supplying an independently reviewed exact parent:

```sh
docker buildx build --build-arg BASE_IMAGE="$PARENT_IMAGE" --target wheel \
  --output type=local,dest="$WHEEL_OUTPUT" .
docker buildx build --build-arg BASE_IMAGE="$PARENT_IMAGE" \
  --build-context wheel="$WHEEL_OUTPUT" -f Install.Dockerfile \
  --load -t "$OUTPUT_IMAGE" .
```

Before installation, `verify_wheel.py` checks complete wheel RECORD coverage,
hashes, allowed package layout, native extension membership, and byte-for-byte
Python runtime source equality. `install.py` rebinds the retained old installation
inventory to actual files and all 370 ownership RECORDs, including nested
installations and resolved paths. It refuses any changed input or unrecorded
runtime payload. It removes only cryptography-exclusive audited files; four
generic documentation files shared with python-barcode remain unchanged. It does
not invoke pip uninstall. Pip installs the real wheel without dependency changes
or generated bytecode, and writes normal metadata including direct_url.json.
Other packages' records and owned files remain unchanged.

The installed receipt records every removed or preserved path and the exact wheel
hash. The ordinary checks exercise Fernet, RSA signing/verification, X509 DER and
PKCS7 signed-data, reporting actual loaded extension/OpenSSL file hashes. The
image build also checks installed dependency consistency. Independent review must
compare the complete layer delta and linked library origins before release.

This is a producer recipe, not a vulnerability disposition. The input inventory
is diagnostic evidence from the retained Jackson parent, whose cryptography
payload also matches the later parser parent. Final release requires exact image
binding, independent source/build/image review, subsequent separately reviewed
stdlib/cache cleanup, and maintained fresh release gates. A final composition
revision label does not assert unknown historical producer source revisions.
