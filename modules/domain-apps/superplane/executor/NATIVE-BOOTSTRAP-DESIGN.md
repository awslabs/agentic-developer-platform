# Native AWS bootstrap implementation for #5927

This is the consolidated implementation design following the approval above. It supersedes the earlier DNS-only proposal. The authoritative Superplane architecture continues to own tenant, workspace and cluster placement. This increment executes against the workspace's already selected dedicated native AWS EKS cluster; it does not choose another cluster or introduce shared-cluster observation authority.

## Approval and execution

An installed regional profile may provide the closed `node_bootstrap` descriptor: version 1, complete `runtime_manifest`, `bootstrap_wrapper_sha256`, and `probe_wrapper_sha256`. Preview validates this descriptor and serializes it canonically as `controller_node_bootstrap` before computing approval digests. The value is bounded by the existing 2000-character parameter limit. Version-4 regional capacity and its approved private-network descriptor are required. The API continues accepting an installed profile selection, never arbitrary commands or caller-supplied runtime defaults.

The exact approved graph is `launch → run-node-bootstrap → status → run-node-probe → deploy → status`, numbered 1–6. Both new names classify as creation-capable through Harness's existing generic `run` rule. Plan validation and provider dispatch enforce the admitted descriptors. The first status checks original Node/GPU readiness; the last checks workload completion and captures results. Legacy profiles keep their four-step graph and task bytes. Teardown retains the original descriptor and source operation and admits only `delete_cluster`.

Opt-in SkyPilot setup is `true`; the task retains its original-deadline sleep and server-owned capacity/org/workspace EC2 tags. It contains neither NodeConfig nor nodeadm invocation. SkyPilot remains the sole allocator. Only the selected original EC2 instances receive subsequent commands, verified against persisted original launch membership, approved account/region/AZ/image/profile and tenant tags. A same-tag replacement is refused.

## Fixed transport and prepared image

`node-command/bootstrap-document.json` is `SuperplaneNativeBootstrapV1`, version 1, SHA256 `02e65ce48a37bd18b64550493fcbeb1cdbcab7f57e667469e60779989417e7a2`, plugin `bootstrap`. Its fixed wrapper deadline is 290 seconds, plugin deadline 300 seconds, and observation bound 360 seconds. `probe-document.json` is `SuperplaneNodeProbeV1`, version 1, SHA256 `41756cc3ea53232d1f22bff56ab5de5e07e9e22fd3a9b8ad6ca372723e0842ef`, plugin `probe`; corresponding bounds are 40, 45 and 120 seconds. Delivery timeout is 30 seconds. The persisted observation deadline is capped by the original runtime deadline and never extended.

Prelaunch checks inspect approved AMI owner/state/architecture/manifest tag and exact installed custom document content/version/owner/hash in every approved region. Postlaunch checks require the original native instance to be SSM Online with the pinned agent version. These read-only checks do not prove effective IAM authorization. [Installation policy](node-command/INSTALLATION.md) specifies supported tenant tag conditions, optional capacity restrictions, native channel policies, and their trust boundaries.

The runtime manifest pins native nodeadm commit `ffc658f85bb8732e130898850802b100aee507e9`, artifact closure, architecture, kubelet/containerd/CNI/NVIDIA runtime/driver/device-plugin/SSM versions. Node wrappers verify root-owned immutable executable/file/tree closure, native IMDSv2 account/region/AZ/instance/image, private DNS/TLS, original deadline and exact contract. The prepared image must mask competing nodeadm boot units before first boot and have no prior init/cache/dropins. CPU image pins and synthetic test manifests are not GPU image provenance. No supported GPU image is published by this change; unresolved artifacts leave opt-in unavailable.

Trusted Plan generates the only permitted public NodeConfig: original cluster endpoint/CA/ServiceCIDR, workspace/allocation labels and allocation NoSchedule taint. No storage/runtime/environment/feature/extra-config or alternate config-source fields are permitted. It travels in the fixed SSM contract, outside SkyPilot task history. Native role authentication supplies node identity. Wrappers suppress native output and emit only bounded identity/digest/state receipts.

Read-only wrapper preflight permits at most three attempts before a persistent fsynced init-start latch. Pinned nodeadm executes once with sanitized environment and bounded AWS SDK retry attempts. A missing/failed completion after the latch never authorizes another init; uncertain partial effects retain the allocation for cleanup. An existing successful matching wrapper receipt may be returned without rerunning init. Full interrupted-init re-entry is outside this approval.

## Database and accounting

Migration `039_controller_node_commands` creates the app-owned journal. Its reference is `superplane-node-command:` plus a digest of original org/workspace/allocation/operation/instance/purpose. Each row holds the original plan digest, admitted step key, exact immutable contract and hash, original instance/account/region, state, first dispatch timestamp, absolute observation deadline, returned CommandId and bounded result. The original operation/instance/purpose tuple is unique. Downgrade refuses to delete nonempty evidence.

A session advisory lock serializes each original command. The domain intent is written first. The existing shared `InventoryAuthority.enumerate_resources` registers the explicit `node_command` dependency with its original step key under existing allocation/lease locks before dispatch. Separate domain and Harness pools are supported; no cross-database join or atomic cross-pool commit is assumed. A crash before registration sends nothing and may resume registration; after entering dispatching, a missing CommandId never permits another SendCommand. Mutation SDK retries are disabled.

A returned CommandId is retained against the existing immutable intent even if authority expires in flight. This narrow historical write grants no new effect or success. Polling checks exact invocation document/plugin/instance/command identity and validates the complete receipt. Success is persisted while the original current shared lease is locked. Existing `task_worker.controller_task` refreshes registration every five seconds and renews the same-fence lease; threaded SDK calls let this loop proceed. Neither a new assignment nor refresh resets a deadline or repeats dispatch.

Inventory reads the original domain journal and original Harness request/intents through their respective pools, verifies request digest/admitted step descriptors, deterministic references and immutable contract binding. The application reference bypasses EC2 ARN construction. Deploy and result capture require the complete original per-instance bootstrap/probe receipt set matching the approved plan and current original launch membership; results recheck this before publication.

## Recovery and validation boundary

Recovery reads exact original CommandIds only. It does not adopt commands through ListCommands/Comment or replay a command. A fresh successful invocation must agree with an already persisted original successful receipt to recover success. Lost receipts remain uncertain. Both creating-call disposition and all inventory dependencies must reconcile before zero exposure; a domain success row alone cannot settle an allocation.

The original command dependency remains present while original compute remains. Only a positive observation of the exact original terminated EC2 instance establishes absence. Stopped, missing, denied or ambiguous inventory and terminal SSM failure do not prove daemon quiescence. Separately authorized teardown continues removing the original compute/network/workload through existing mechanisms.

Remote tests cover the approved graph and legacy task behavior; real PostgreSQL transport/journal/shared-membership and split-pool recovery; original-instance replacement refusal; lost responses, interrupted registration and late handles; invalid invocation receipts; production Provider dispatch and deploy/result refusal; fixed wrapper integrity/latch behavior; and real paid-task refresh across assignment expiry. The direct transport fixture uses a reduced admitted graph and simulated AWS. The Provider branch test substitutes Plan parsing, SkyPilot cloud setup and request bookkeeping; it does not claim a full live six-step execution. No runtime tests are run locally.

Pinned-image live GPU join, CNI/device-plugin compatibility, image pull and ordinary pod networking remain required external acceptance evidence. No deployment, AMI publication or spending is authorized here. Continue AWS recovery/workload/demo stories next; Azure/GCP remain last.
