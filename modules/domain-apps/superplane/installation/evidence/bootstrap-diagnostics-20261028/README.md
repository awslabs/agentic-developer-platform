# Original bootstrap diagnostic source qualification

The four recorded diagnostic sessions on worker
`superplane-paid-worker-ph9zp-pmt7b` used exactly the two programs preserved here
as text. The installation collector can qualify these eight CloudWatch stage
records only for the recorded pod UID, creation event, immutable image,
container, volumes, operator identity, request URIs, timestamps and source bytes.
Ordinary planning retains its prohibition on exec. Additional or incomplete
diagnostic history, attach and ephemeral containers remain refused.

Both programs import only the standard library, parse JSON as data, inspect
process/cgroup/socket metadata and stat a fixed artifact list. The later version
opens bootstrap state read-only, without following symlinks, validates its scope
and reports selected booleans. Neither evaluates input, starts subprocesses,
opens a network connection or performs a filesystem mutation. The image has a
read-only root filesystem and default working directory `/`; its inspected
configuration has no Python import-path override. The exact container and
mount digests exclude a writable interpreter, standard library or working
directory replacement.

The pod also inherited the mutable `superplane-paid-worker-config` ConfigMap.
The collector therefore reads its exact current UID/version/data, proves no
ConfigMap mutation in the complete protected audit window since source creation,
and verifies an unchanged readback. The data has no Python environment override.
Keep that ConfigMap at the recorded 055 version until owner evidence has been
published; then deploy the replacement runtime. These source checks do not
depend on the new API deployment.

Kubernetes audit does not record stdin bytes. The input read is not size-bounded,
the state mount can be selected subject to the program's checks, and extra JSON
fields can be echoed. The qualification establishes absence of a diagnostic
mutation mechanism; it does not establish exact stdin, successful script exit,
bounded CPU/memory use, or absence of every possible read. HTTP 101 records the
stream upgrade, not success of the diagnostic program. These records never
authorize another diagnostic session or replace the native cleanup, expiry,
retained settlement, human review and resume checks.
