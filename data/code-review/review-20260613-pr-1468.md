- `invocation_status.py:20`: Module-level `_table_name = os.environ.get("WEBHOOK_EVENTS_TABLE", "")` is evaluated at import time. If the env var is set after import (unlikely in container context but possible in tests), the module re-checks at L48 (`table = _table_name or os.environ.get(...)`). This is correctly handled — the fallback at L48 ensures runtime env var reads still work. **No action needed.**

- `handler.py:775`: `installation_id` parameter typed as `int` but the existing code at L580 passes it from `installation_id` which is parsed from the payload as an int. At L827 it's cast to `str(installation_id)` for the DDB write. Consistent with existing patterns — **no action needed.**

This is pre-existing dead code (the GSI was always named `tenant-index` in TF but `gsi1` in the query code). **Not introduced by this PR** — file as follow-up.
