### MEDIUM — discuss before merge
- **`org/repo/src/db.py::symbol` ambiguity (L81-88 in test)**: when a `::` target has 3+ parts and the last has a dot, it falls back to `_extract_repo_id()` which takes only the first component as repo. This means `"org/repo/src/db.py::connect_db"` → `repo="org"`, which is technically wrong (should be `"org/repo"`). However:
  - The test documents this explicitly as the "ambiguous case"
  - The fix correctly notes that `resolve_symbol` handles recovery at query time
  - This is NOT a regression — the old code had the same behavior
  - The critical fix (the issue's actual bug) is the `org/repo::symbol` case (no file), which is now correct
  - Fixing this edge case would require a more complex heuristic and could break the eval corpus. A follow-up issue is appropriate if it becomes a real problem.

### LOW — follow-up candidates
- **The `_extract_repo_id_for_symbol` 3+-component-no-dot case** (line 975-977): `"a/b/c::sym"` → `repo_id="a/b/c"`. This is unusual (3-component repo names don't exist on GitHub) but harmless — Neptune's `resolve_repo_name` would normalize it. Could add a test case for documentation.
- **Import placement in tests**: `from unittest.mock import patch` and `from door.structural_backend import _impact_via_neptune` are inside test methods rather than at module top. This is a style choice (keeps tests self-contained) and doesn't affect correctness, but differs from the rest of the file. Not worth changing.
