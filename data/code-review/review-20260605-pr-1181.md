## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge

**1. Unused `execSync` import in `token-refresh.ts` lint risk** (line 10)

The `execSync` import is retained because `execWithFreshToken()` uses it. This is correct and intentional. No action needed.

**2. `cloneRepo()` in GitHubClient.ts no longer calls `getToken()`** (line 33)

The original code called `const token = await this.tokenManager.getToken()` and embedded it in the URL. The new code uses a username-only URL (`https://x-access-token@github.com/...`) and relies on `GIT_ASKPASS` to provide the password. This works because `GIT_ASKPASS` reads from `process.env.GITHUB_TOKEN`, which is set by the entrypoint before the GitHubClient is used. However, calling `getToken()` before clone had the side-effect of ensuring the token was fresh. With the new approach, the token freshness depends on `process.env.GITHUB_TOKEN` being current at clone time — which it is, since the entrypoint just minted it.

This is a **non-issue** for the current flow (entrypoint mints → clone immediately after). If clone were ever called much later in the lifecycle, `GIT_ASKPASS` reading a stale env var could cause a 401. But the existing refresh timer in `TokenManager` and the `getToken()` call before push in `commitAndPush()` handle that path.

Verdict: acceptable as-is. The pre-push `getToken()` ensures freshness for the only operation that could encounter token expiry.

### LOW — follow-up candidates

**1. Process table token exposure in entrypoint.py**

The architect noted (finding 🟡 #5) that `run_cmd(["git", "clone", ..., clone_url])` still exposes the username in the process table. With the username-only URL (`x-access-token@github.com`), the password is no longer in the process table — this is actually fixed by this PR as a side benefit.

**2. `import { execSync } from 'child_process'` still in token-propagation.test.ts**

The test imports `execSync` to create `mockedExecSync` for asserting it's NOT called. This is correct test pattern.

## Recommendation

**APPROVE** — All acceptance criteria met. No merge blockers. The implementation is clean, minimal, and matches the architect's approved design exactly. TypeScript compiles cleanly, all 8 token-propagation tests pass.
