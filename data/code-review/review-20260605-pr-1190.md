## Findings (by confidence)

### HIGH — merge blockers
None.

### MEDIUM — discuss before merge

1. **monitoring.ts L1999**: `reassessContext.analysis` is wrapped with `JSON.stringify()` before `wrapUntrusted()`. The `StateAnalysis` object is medium-risk (internally generated), so `JSON.stringify` is the correct approach, but it adds verbosity to the prompt. Acceptable trade-off for consistency. Non-blocking.

2. **CodeGenerationAgent.ts L151-157**: The wording change from "FOLLOW THESE EXACTLY" / "ORIGINAL ISSUE takes priority" to "Follow the plan" is a behavioral change beyond pure wrapping. This is **correct for security** (previously the model was instructed to prioritize untrusted issue body over the approved plan), and the approved design explicitly sanctioned this change. Non-blocking, but worth noting for 48h soak monitoring.

3. **agent-worker.ts L674**: `commentsContext` contains ALL comments including other agent outputs. Wrapping the entire blob means the preamble appears twice in one prompt (once for `issue.body`, once for `commentsContext`). This is defense-in-depth — two boundaries is more secure than one, and model verbosity cost is negligible (<200 tokens). Non-blocking.

### LOW — follow-up candidates

1. **Preamble duplication**: The preamble appears multiple times in prompts that wrap both `issue.body` and `commentsContext`. A follow-up could add a `wrapUntrustedBrief()` for secondary inputs that only includes delimiters without the full preamble. Low priority — current approach is safer.

2. **Line number drift**: The caller audit table in the PR body references specific line numbers. These will drift with future edits. Low priority — the function names are more stable anchors.
