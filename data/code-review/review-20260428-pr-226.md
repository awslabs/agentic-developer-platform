## Findings (by confidence)

### HIGH -- merge blockers (FIXED)
- **cape-host.tf:202-204, all 4 bootstrap scripts**: IMDSv2 incompatibility. Instance has `http_tokens = "required"` (IMDSv2) but all IMDS calls used bare `curl` without session tokens. These would return 401, breaking instance tagging and all bootstrap scripts that retrieve INSTANCE_ID/REGION.
  - **Fixed in commit 62adc2d**: Added IMDSv2 token fetch before all IMDS call blocks.

### MEDIUM -- discuss before merge
- **01-cape-deps.sh:90**: Hardcoded PostgreSQL password `cape_sandbox_dev`. Low blast radius (local PG on isolated private host, SSM-only access), but future hardening should read from Secrets Manager. Acceptable for dev; document for prod.
- **variables.tf:90-94**: `adp_eks_security_group_id` variable is defined but never referenced. Issue spec says ALB should use cross-SG reference from ADP EKS pods, but implementation uses CIDR-based filtering (`var.adp_vpc_cidr`). CIDR approach works functionally; cross-VPC SG refs need specific peering config. Unused variable is harmless but should be wired up or removed in follow-up.
- **peering.tf:188**: VPC peering route destination is `var.vpc_cidr` (full 10.100.0.0/16) instead of just the private subnet CIDRs where the ALB lives. Slightly broader than the issue spec's "narrow as possible". Acceptable since the VPC is entirely controlled infrastructure, but could be tightened.
- **04-hardening.sh:96-124**: CloudWatch alarm creation requires `cloudwatch:PutMetricAlarm` and the health metric cron needs `cloudwatch:PutMetricData`, neither of which is in the CAPE host IAM role. The script handles failures gracefully with `|| echo "WARNING..."`, but the acceptance criteria says "CloudWatch alarms exist". These need to be created from outside (e.g., Terraform) or the IAM policy needs expansion. Issue says "do not widen IAM beyond listed permissions", so Terraform-managed alarms would be the correct fix -- follow-up issue.

### LOW -- follow-up candidates
- **03-windows-vm.sh:97-108**: `virt-install` uses `--graphics spice,listen=127.0.0.1` which binds SPICE to localhost only (good), but the script could note that SSM port forwarding is needed to access it.
- **01-cape-deps.sh:32**: `mongodb-org` package may not be in Ubuntu 22.04 default repos, but the fallback on lines 40-48 handles this correctly.
- **04-hardening.sh:156-161**: SG tightening is documented as a manual follow-up but not automated. Consider adding a Terraform variable to toggle between "bootstrap" (broad) and "hardened" (restricted) egress.
