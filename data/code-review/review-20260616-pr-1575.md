## PR Title
fix(ingest): inject NEPTUNE_ENDPOINT into ingestion job for SCIP graph loading

## Summary
PR fixes the root cause of SCIP graphs never reaching Neptune: the ConfigMap was
deployed with `GRAPHRAG_ENABLED=false` (default in `config.env`), which causes
`NEPTUNE_ENDPOINT=""` in the pod env. The SCIP loader's Step 6 has
`if NEPTUNE_ENDPOINT:` which correctly skips when empty. Fix: inject the actual
Neptune endpoint directly into the job env at workflow level.

### MEDIUM — discuss before merge
- **Hardcoded Neptune endpoint**: The endpoint `adp-dev-eks-cluster-graphrag.cluster-civhekhiupfe.us-east-1.neptune.amazonaws.com` is hardcoded at workflow level (line 110). Ideally this would be read from SSM or Terraform output at runtime. However, this is consistent with the existing pattern in `agent-context-verify.yml` (line 211), and is acceptable for the dev environment. A follow-up could parameterize this via SSM lookup.
- **Double fallback on RBAC**: The deploy workflow now has both `continue-on-error: true` at the step level AND `|| echo "WARNING..."` inside the run block. The former is sufficient — the `||` is redundant but harmless.

### LOW — follow-up candidates
- The `GRAPHRAG_ENABLED` ConfigMap should be updated to `true` once Neptune is confirmed working, which would make the workflow-level injection redundant for future runs.
- Consider adding a verification step after job creation to confirm NEPTUNE_ENDPOINT is non-empty in the pod spec (defense against copy-paste errors).
