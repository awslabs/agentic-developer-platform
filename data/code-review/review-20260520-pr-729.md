## Findings (by confidence)

### HIGH — merge blockers

### MEDIUM — discuss before merge
- `service.py`: The personal-account filter uses `m.provider_scope_id.endswith(f":{caller_user_id}")`. This is an in-Python filter (post-query), which is correct for SQLite compatibility in tests. At scale with many adp-default rows this could be slower than a DB-level LIKE, but acceptable for v1 given the comment in approved design about "in-Python filter pattern wherever JSON column predicates are involved."
- The `install_metadata` column is named `metadata` in the DB (via `mapped_column("metadata", JSON, nullable=True)`) to avoid collision with SQLAlchemy's reserved `metadata` attribute. This is a valid workaround but worth noting in code comments for future maintainers.

### LOW — follow-up candidates
- Legacy rows (pre-#724) will be invisible until backfill or reinstall. The approved design accepts this. A follow-up backfill script issue should be filed.
- `configure_url` now uses `https://github.com/settings/installations/{id}` (user-level settings page) instead of the org-level URL. This works for both org and personal accounts but the org path `https://github.com/organizations/{login}/settings/installations/{id}` would be more precise for org installs. Minor UX.
