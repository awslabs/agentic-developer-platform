2. **Unused variable `all_symbols` (line 136, 158)**: The set `all_symbols` is populated in `build_reference_graph()` but never used. Minor dead code — not a blocker for a spike script.

3. **`type_refs` counter always 0 (line 319)**: The `type_refs` variable is initialized but never incremented (no condition matches it in the loop). The characterize function prints "Type/class annotations: 0 (0%)" which is misleading — it's not that there are no type refs, it's that the classification logic doesn't identify them. Cosmetic issue only for a spike script.

### LOW — follow-up candidates

1. **Import order**: `from collections import Counter, defaultdict` after `import scip_pb2` (which itself follows a `sys.path.insert`). Non-standard but necessary due to the `sys.path` manipulation. Standard practice for protobuf-dependent scripts in isolated environments.

2. **Documentation completeness**: The spike docs file shows only 3 sample edges in the table (not 5). The issue comment showed 5. Minor discrepancy — the script would produce 5 when run. Not a blocker.

3. **Enclosing-scope heuristic uses "last def at or before line"**: The script's comment says "the definition whose range ENCLOSES P" but the implementation finds "last def whose start_line <= ref_line" — this is "enclosing or preceding" not strictly "enclosing". Works for Python's flat function model but noted for accuracy. The spike doc correctly acknowledges this limitation.
