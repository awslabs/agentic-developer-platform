## Invariant audit — "the envelope is not a budget"

The PR claims this is enforced by *shape*, not care. I verified that claim rather than
taking it:

- `PersonEnvelope` in `types/budget.ts` declares **no** `cap_usd`, `remaining_usd`,
  `utilization_pct`, or `band` (checked by parsing the interface body). There is no
  denominator field to bind, so a progress bar is unbindable, not merely discouraged.
- This matches `PersonEnvelope` in `modules/gateway/src/budget/schemas.py:402` exactly,
  including `is_budget: Literal[False]` → `is_budget: false`.
- `PerOrgLine`: all five fields (`org_id`, `org_name`, `cloud_spend_usd`,
  `cap_usd: str | None`, `is_active_partition`) match `schemas.py:352` in name, type and
  nullability.
- Response optionality is correct and for the right reason: backend has
  `default_factory=list` / `default=None`, so the backend always sends them; `?` exists
  only to tolerate a pre-#4640 response.
- The 5 grep hits for `progressbar|band|utilization|remaining|headroom` in
  `PerOrgSpend.tsx` are **all in doc comments** — zero rendered cap vocabulary. Confirmed
  line by line.

`null` cap → `'No cap set'` (`PerOrgRow`), never `$0.00`. Correct per the issue's reasoning
and consistent with the existing `BudgetLineRow` convention.

No cross-partition summing leaks into the existing sections: `BudgetLines`,
`combined_informational`, and the headline are untouched by the diff.

## Findings

### HIGH — merge blocker (FIXED on branch in `bfe8b7e`)

**`src/components/budget/PerOrgSpend.tsx:37` — `IdentityStatus` used but never imported;
`tsc` fails, so the frontend build and deploy fail.**

`PerOrgSpendProps` declares `identityStatus: IdentityStatus | undefined` (line 164,
introduced by the self-review commit `c759626`), but the import on line 37 brought in only
`PerOrgLine` and `PersonEnvelope`. There is no ambient declaration — `IdentityStatus` is
exported from `types/budget.ts:50` and referenced nowhere else outside that file — and
`tsconfig.json` includes this path with `strict: true`. Result: `TS2304: Cannot find name
'IdentityStatus'`.

*Why every green check missed it, and why this is the interesting part:*

- **Frontend Unit Tests** (`gateway-ci.yml:173`) runs only `npx vitest run`. Vitest
  transpiles TSX through esbuild, which **strips** type annotations without checking them.
  A missing *type-only* import is therefore invisible to all 1360 passing tests — the
  suite genuinely cannot fail on it.
- **eslint** cannot catch it either: `eslint.config.js` uses
  `tseslint.configs.recommended`, the **non**-type-checked preset, and typescript-eslint
  disables core `no-undef` for TS files by design, deferring exactly this class of error to
  the compiler.
- Only `tsc` sees it — and no CI job runs `tsc`.

*Blast radius if merged unfixed:* `npm run build` is `tsc && vite build`, so
`gateway-deploy.yml:582` and `deploy-frontend.sh:110` both die at the `tsc` step. No bundle
is emitted, nothing syncs to S3, no CloudFront invalidation — the `/budget` page ships
none of this feature, and the failure surfaces at deploy time rather than in review.

This is also why the PR description's "`tsc --noEmit` — clean" claim could not be
reproduced: it is inconsistent with the code as pushed. The check was presumably run
before `c759626` added the `identityStatus` prop and not re-run after.

**Fix applied** (one line, safe, per the reviewer guideline on small fixes):

```diff
-import type { PerOrgLine, PersonEnvelope } from '@/types/budget';
+import type { IdentityStatus, PerOrgLine, PersonEnvelope } from '@/types/budget';
```

Verified by parsing the module's import bindings and every type-position identifier: after
the fix, **zero** unresolved type references remain, and all three imported types are
genuinely exported from `types/budget.ts`.

### MEDIUM — worth a follow-up, not a blocker on this PR

**No CI job type-checks the frontend.** This PR is evidence the gap is load-bearing: a
build-breaking error passed Lint, Frontend Unit Tests, and 7 security scanners. Adding a
`npx tsc --noEmit` step to the Frontend Unit Tests job in `gateway-ci.yml` would have
caught it in seconds. Worth filing separately — it protects every future frontend PR, not
just this one.

### LOW — informational

1. **`runs-scope-note` has no test.** The caption added at `BudgetSpend.tsx:289` (gated on
   `per_org.length > 1`) is the one new rendered element with no assertion. Low risk —
   it's static copy — but it's the only untested line in the diff.
2. **Redundant `lines.length > 0 &&` guard** at the row-map site: unreachable, because the
   function already `return null`s on `lines.length === 0` above it. Harmless; a future
   reader may pause on it.
3. **`data-active-partition` boolean attribute.** React omits the attribute entirely for
   `false` rather than writing `"false"`. Current tests assert on the badge, so behavior is
   consistent — noted only because a future test reading
   `data-active-partition="false"` would fail.

## Security review

No qualifying vulnerabilities. Detail in the separate security comment; summary:

- **XSS/DOM injection:** none. Zero `dangerouslySetInnerHTML`, `innerHTML`, `eval`,
  `new Function`, `document.write`, or `href`/`src` binding in the new or modified files.
  Every server string (`org_name`, `note`, `org_id`, money fields) is a JSX text child or a
  `data-*` value — both React-escaped. All `className`s are static literals.
- **Data exposure:** no new surface. The cross-org identity `anchor` is typed and
  fixtured but never reaches the DOM. No `console.*`, no `localStorage`/`sessionStorage`,
  no token handling.
- **Injection/crypto/authn:** N/A — no network calls, no path or file ops, no auth logic.
  Only parsing is `Number()` in `formatMoney`, guarded by `Number.isFinite`.
- **Fixtures:** MSW-only, gated behind `import.meta.env.DEV`; the placeholder
  `anchor: 'github:12345678'` is not a credential.
- The repo-wide security-scan comment (8011 findings) is baseline noise across Python,
  Terraform and container layers — **nothing in it maps to these 5 TypeScript files.**

`formatMoney` deserves positive mention: it correctly handles `Number('') === 0`,
`'Infinity'`, and `-0.004` → not `-$0.00`, and keeps a 4dp sub-cent branch so real sub-cent
foreign-workspace spend cannot render as `$0.00` on the very row built to disprove a `$0`
reading. That is the issue's own thesis applied to its own rendering path.
