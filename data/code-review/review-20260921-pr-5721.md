## Fixes applied (commit `c33137cd`)

| # | Finding | File | Fix | Evidence |
|---|---|---|---|---|
| 1 | `denylist.check_url()` parses URLs with Python's `urlparse`, which reads `http://169.254.169.254\@good.com/` as host `good.com` (text after the last `@`). WHATWG URL parsing — what Chromium/CDP actually use — treats `\` as `/` for http(s), so the real browser connects to `169.254.169.254`. Reproduced: `check_url(...)` returned `allowed=True` for a URL that actually points at the AWS metadata endpoint. | `denylist.py`, `browser_guard.py` (`_host_of`) | Added `normalize_backslashes()`; applied before `urlparse` in `check_url` and `_host_of`. | `test_backslash_before_at_is_read_as_the_real_host`, `test_backslash_variant_of_loopback_is_refused`, `test_ordinary_url_without_backslash_is_unaffected` |
| 2 | `NavigationGuard` cached every *non-target* host's decision forever after its first check. The analysis target's page is fully attacker-controlled and can load a subresource from a domain it owns; that domain can resolve publicly once (cached "allowed"), then rebind DNS to an internal address for a later request in the same page load and sail through on the stale cached verdict. Identical bug class to the one fixed for the target host in `f4b5243` — just left open for every other host. Reproduced with a scripted two-request sequence: request 2 was allowed through with 0 additional DNS lookups. | `browser_guard.py` (`NavigationGuard.decide`) | Removed the per-host cache entirely; every request is re-resolved and re-checked. | `test_third_party_subresource_rebinding_after_a_permitted_request_is_aborted` (replaces the old caching test, which asserted the now-removed behaviour) |
| 3 | `guard_page()` only called `page.route()`. Playwright's own docs: this "will not intercept the first request of a popup page" and never sees WebSocket traffic (routed via a separate `route_web_socket` mechanism). The analysed page is attacker-controlled and can open `window.open()`/`new WebSocket(...)` to reach an unvetted destination with zero checking. | `browser_guard.py` (`guard_page`, new `NavigationGuard.handle_websocket`) | Route on `page.context` instead of `page` (covers popups — context routing applies to every page the context creates) and add `route_web_socket` with a `handle_websocket` handler; falls back to page-level routing if no `.context` is exposed (keeps the existing `FakePage` test double working). | `test_guard_routes_on_the_context_not_just_the_page`, `test_websocket_to_internal_address_is_closed`, `test_websocket_to_permitted_address_connects` |

All four were reproduced against the actual code (not inferred from reading the diff) before fixing, and each fix has a regression test proving it closes the gap.

**Not fixed — disclosed as a follow-up, not a blocker:** Service Workers registered by the analysed page can issue `fetch()` calls that bypass Playwright's request interception entirely (Playwright's docs recommend `service_workers="block"` on `new_context()` when using request interception, and none of the six example scripts set it). This is lower-confidence (0.7) than the four fixed issues, and — unlike them — fixing it means touching context-creation call sites in all six `examples/*.py` scripts, which is a larger, more scope-expanding change than a same-task reviewer repair should make silently. Recommended as a fast follow-up issue; does not block this PR, since it narrows rather than eliminates the coverage this PR adds (HTTP(S) fetches, redirects, WebSockets and popups are all covered).

## Functional review (developer's original three commits)

Verified independently, not from the PR description:
- **Canonicalisation** (`canonical_address`, `_parse_alternate_ipv4`, `_unwrap_embedded_ipv4`): tested integer/octal/hex IPv4, IPv4-mapped/6to4/NAT64 IPv6 forms, and overflow/malformed edge cases directly — all correct, no exceptions on malformed input.
- **Classification-first decision** (`check_address`/`_classify_blocked`): confirmed the CIDR list (`100.64/10`, `192.88.99/24`, `198.18/15`, `240/4`, plus IPv6 equivalents) is the second layer behind stdlib classification, and that `192.88.99.0/24` (globally-routable per `is_global` with no other flag) is correctly caught only because it's explicit — matches the design's stated rationale.
- **Fail-closed resolution**: unresolvable hostnames refuse with a distinct `resolution_failed` code (not `blocked_address`), and a hostname resolving to a mix of allowed/blocked addresses is refused — both verified by direct test.
- **Connection-boundary enforcement**: `start_guarded_session` vets before constructing a client (verified: the `client_factory` in the structural-enforcement test is never called for a refused destination), and all six `examples/*.py` route through `start_guarded_session` + `guard_page` before their first `page.goto`, matching the "no code path that browses an unvetted address" claim in `browser_guard.py`'s docstring.
