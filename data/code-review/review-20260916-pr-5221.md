## Blockers (fixed in this follow-up)

### F1 — Recovery sweep reported `clean` without verifying termination
`.github/workflows/eval-cli-uplift.yml` (sweep step) · `tests/e2e/cli_uplift/cleanup.py:recovery_report`

`clean` was computed as `{expired ids} == set(terminated)`, where `terminated` was appended
on the terminate **call** returning zero. No `describe-instances` re-read. An instance held
by `DisableApiTermination`, or stuck in `stopping` behind a lifecycle hook, accepts
`terminate-instances` with exit 0 and stays alive — reported as recovered.

The in-run path already did this correctly (`live.py:488-504` polls until state is
`terminated`, raising `PortError` otherwise). The sweep, which runs when the manifest is
gone, lacked the same proof.

**Fix:** `recovery_report(expired, observed, *, ttl_minutes)` now takes a mapping of
instance ID → state observed by a re-read *after* the terminate call, so the shape cannot
be misused. Only `terminated` counts as clean; `shutting-down` is deliberately outstanding.
The workflow polls `describe-instances` (24 × 5s) and reports observed state per instance.

### F2 — `LaunchTime` parsed as local time
`.github/workflows/eval-cli-uplift.yml` (sweep step)

`time.mktime(time.strptime(stamp[:19], ...))` interprets EC2's UTC `LaunchTime` as local.
Measured skew: `+420` min under `America/Los_Angeles`, `-540` under `Asia/Tokyo`.

Reproduced end-to-end on a genuinely 360-minute-old instance with `ttl_minutes=240`:

| Runner TZ | Age the old code reported | Outcome |
|---|---|---|
| `UTC` | `+360` min | expired correctly (masks the bug) |
| `America/Los_Angeles` | `-60` min | **NOT EXPIRED → leaks, sweep reports clean** |
| `Asia/Tokyo` | `+900` min | expired far too early → can kill a live run's instance |

So the defect cuts both ways: west of UTC leaks, east of UTC over-terminates. Masked today
only because ARC runners resolve to UTC and nothing pins `TZ`.

**Fix:** new tested `cleanup.launch_epoch()` uses `calendar.timegm` (the UTC-correct inverse
of `strptime`), accepts an already-numeric epoch, and returns `None` on an unparseable stamp
so `expired_instances`' existing "cannot prove age → leave it to the manifest path" rule is
preserved. `expired_instances` now calls it, moving the conversion from untested inline
workflow YAML into the library.

**Why CI never caught F2:** every pre-existing sweep test passed `LaunchTime` as a float,
so the string conversion was never exercised. The new tests drive the string path under
non-UTC `TZ`.
