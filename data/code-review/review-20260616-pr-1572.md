### MEDIUM — discuss before merge (non-blocking)
- **Potential silent failure**: `continue-on-error: true` means if the StorageClass is genuinely missing AND can't be created, the workflow proceeds but PVC claims will fail later at deploy time. This is acceptable because: (a) the SC exists from initial cluster provisioning, and (b) the in-script `kubectl get storageclass` check will report the correct status in the log. Still, a downstream step that validates `kubectl get sc ebs-gp3` exists before creating PVCs would be ideal as a follow-up.
- **Branch accumulation**: The Dockerfile change (`cmd/scip-go` fix) is identical to what PR #1571 already merged. Both PRs landed from `agent/issue-1553` branch, so this is branch accumulation (not duplicate work) — the squash merge is clean.

### LOW — follow-up candidates
- Consider adding a validation step after StorageClass that confirms `ebs-gp3` is available (either pre-existing or just created), with a clear error if not.
