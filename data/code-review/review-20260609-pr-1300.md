## Findings (by confidence)

### HIGH — merge blockers
None.

### MEDIUM — discuss before merge
1. **Loop-level import** (`experience_tool.py:208`): `from .storage import build_entry_path` is imported inside the `for` loop body in `_recall()`. Python caches module imports so this works, but it's unusual style. The import could be moved to the top-level imports (alongside `from .storage import PersonalContextStore`). Non-blocking since it's functionally correct.

2. **`synthesized` extra field** (`experience_tool.py:139`): `entry_data` includes `"synthesized": False` but `PersonalContextEntry` has no `synthesized` field. Pydantic's default `extra="ignore"` silently drops it. This is harmless now but confusing for future readers. Could be removed from the dict since it's a no-op. Non-blocking.

3. **In-memory embedding index** (`experience_tool.py:59`): `self._embeddings: dict[str, list[float]]` stores embeddings in the tool instance. This means embeddings are lost on pod restart (entries persist in AGFS but their embeddings don't). The design doc acknowledges this ("future: persist in AGFS alongside entry"). This is acceptable for the current phase but should be addressed before production use. Tracked as future work per design.

### LOW — follow-up candidates
1. **Negative control test assertion** (`test_experience_tool.py:331`): The test asserts `r["score"] < 0.8` which is a fairly generous threshold. With the bag-of-characters fake embedder, most English text will have non-trivial similarity due to common letters. The test still validates the intent (unrelated = lower score than related) by checking the score isn't near 1.0. Fine for a unit test.

2. **e2e test formatting changes** (`test_mcp_endpoint.py`): The diff includes reformatting of existing `call_tool()` invocations (multi-line with trailing commas). These are style-only changes (ruff format). The functional change is just 5→6 tool count.

## Security review
- **Cross-user isolation**: Verified. `recall` goes through `store.list_entries(identity)` which calls `_caller_can_read()` — owner sees own private entries; non-owner only sees same-tenant shared entries. Test `test_different_owner_sees_nothing` confirms this.
- **Input validation**: All user inputs validated (action enum, persona enum, visibility enum, non-empty content/query). Invalid inputs produce `ExperienceToolError`, not 500s.
- **No secrets committed**: No API keys, tokens, or credentials in the diff.
- **No path traversal**: Owner sub is validated as UUID format (via `require_identity` → `extract_identity` → `is_valid_uuid`). Tenant ID is non-empty string.
- **No injection risk**: No SQL, no shell commands, no eval. Data flows are content → embed → store as JSON.
- **httpx usage in embeddings.py**: Uses `httpx.post()` with a configurable URL (defaults to in-cluster service). No SSRF risk in production (NetworkPolicy restricts access). `response.raise_for_status()` properly propagates errors.
- **Dependencies**: Uses `python-ulid` (ID generation), `httpx` (HTTP client), `pydantic` (validation) — all established, audited libraries.
