## Findings (by confidence)

### MEDIUM — discuss before merge

- **`local.peering_eks_sg_id` is defined but never consumed** (`peering.tf:25-28`). The variable `var.adp_eks_security_group_id` was also unused in the original code (never referenced in any resource). This is pre-existing dead code that the PR faithfully migrates to the new pattern. Not a blocker — it's correctly wired for future use (e.g., if an SG ingress rule is added for EKS-to-CAPE traffic). Should be noted as pre-existing.

- **`peering_vpc_cidr` sentinel logic** (`peering.tf:18-20`): Uses `var.adp_vpc_cidr != "10.0.0.0/16"` as a sentinel to detect "not explicitly overridden." This works because the variable default is `"10.0.0.0/16"` and the tfvars no longer sets it. Slightly unconventional but correct given `coalesce()` skips empty strings. If someone explicitly sets `adp_vpc_cidr = "10.0.0.0/16"` thinking they're overriding, it won't take effect — but that's an edge case (you'd only override if the CIDR was different).

### LOW — follow-up candidates

- **Pool ID echoed to workflow logs** (`fix-gateway-infra-drift.yml:63`): `echo "Cognito Pool ID: $POOL_ID"` prints the pool ID to workflow logs. Cognito pool IDs are not secrets (they're in every JWT), but some orgs treat them as semi-sensitive. Very low risk — the workflow already runs on org-private runners. Could be removed in a follow-up if desired.

- **Pre-existing: `account_id = "879318057152"` in terraform.tfvars** — Intentionally out of scope (#1156). Noted for tracking.
