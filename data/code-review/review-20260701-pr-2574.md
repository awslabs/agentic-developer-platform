# Review of PR #2574

## Driving issue
- #2574 / #2564: fix(gateway-infra): route Lambda layer builds through CodeBuild

## Acceptance criteria checklist
- [x] **Removes Docker dependency from gateway-infra-apply** — PyJWT step no longer calls `./build.sh` locally; psycopg2 step no longer triggers `gh workflow run`. Both now use `./.github/actions/codebuild-run` composite action.
- [x] **Eliminates stale source-zip dependency** — `codebuild-run` composite action uploads source per-build to `codebuild/src/${SHA}-${RUN_ID}.zip`, not the old `codebuild/adp-source.zip`.
- [x] **Adds "Ensure CodeBuild projects exist" step** — New step at line 105 creates/updates both `adp-dev-pyjwt-layer` and `adp-dev-psycopg2-layer` projects, guarded by `batch-get-projects` existence check.
- [x] **Idempotent on re-run** — Both layers check S3 first via `s3api head-object` and skip the build if artifacts already exist.
- [x] **Fresh-deploy case handled** — Role existence is validated first (hard fail if `platform-infra` not applied); projects are created if missing.

## Findings (by confidence)

### HIGH — merge blockers
None.

### MEDIUM — discuss before merge

1. **Terraform state drift risk (low-impact):** The "Ensure CodeBuild projects exist" step creates/updates CodeBuild projects via CLI. These same projects are Terraform-managed in `platform/infra/modules/codebuild/main.tf`. On the NEXT `platform-infra-apply`, Terraform will detect drift (e.g. missing `logs_config`, missing `SECURITY_SCANS_BUCKET` env var) and attempt to update the project to match its desired state. This is acceptable for a fresh-deploy bootstrap scenario but should be documented in a comment.
   - **Suggestion:** Add a comment like `# Bootstrap-only: Terraform reconciles on next platform-infra-apply` in the step.
   - **Severity:** Non-blocking — Terraform self-heals, no data loss, no runtime impact.

2. **WIP commit in history:** The first commit (`ba26ca4`) is `WIP: agent/developer starting #2564` — an empty marker commit. This is cosmetic; squash-merge resolves it.

### LOW — follow-up candidates

1. **Environment variable expression inconsistency:** The shell steps use `${TF_VAR_environment:-dev}` (bash default) while `uses:` steps use `${{ env.TF_VAR_environment || 'dev' }}` (GitHub expression). Both evaluate correctly since `TF_VAR_environment` is always set to `dev` at workflow level (line 41). Purely cosmetic, no functional impact.

2. **No `set -e` in the S3 check steps:** The `pyjwt_check` and `psycopg2_check` steps don't include `set -e`. This is fine because they only run a single conditional command and write to `$GITHUB_OUTPUT` — no multi-command failure to propagate. But adding `set -e` would be consistent with other steps.

3. **Orphaned workflow file:** `psycopg2-layer-build.yml` still exists in the repo. The PR removes the reference to it from `gateway-infra-apply.yml`, but the workflow file itself remains. It may still have value for standalone rebuilds, so this is not a bug — just worth noting.

## Correctness Analysis

1. **Build flow is sound:** Check S3 → skip if exists → build via CodeBuild → artifact lands in S3. Matches the pattern used by other layer builds in the repo.
2. **Composite action usage is correct:** `codebuild-run` handles source upload, build start, and polling. The `environment_variables` format matches the action's expected input.
3. **Project name derivation matches Terraform:** `adp-${TF_VAR_environment:-dev}-pyjwt-layer` matches `${var.name_prefix}-pyjwt-layer` where `name_prefix = "adp-${var.environment}"`.
4. **Role name derivation matches Terraform:** `adp-${TF_VAR_environment:-dev}-codebuild-role` matches `${var.name_prefix}-codebuild-role`.
5. **Buildspec paths are correct:** `codebuild/bs-pyjwt-layer.yml` and `codebuild/bs-psycopg2-layer.yml` both exist in the repo with valid buildspec content.
6. **YAML syntax validated:** The modified workflow passes YAML parsing without errors.

## Recommendation
**APPROVE** — The change is correct, solves the stated problem (Docker dependency + stale source-zip dependency on fresh deploys), and introduces no security concerns. The Terraform drift risk is self-healing and acceptable for a bootstrap path.
