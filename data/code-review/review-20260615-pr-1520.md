## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge

1. **D11 naming inconsistency**: The decisions table (D11) says unique key is `repo` + `file` + `symbol` + `kind`, but the actual property name in the schema section is `name` (not `symbol`). The Cypher constraints correctly use `s.name`. The word "symbol" in D11 is ambiguous — a developer agent might create a property called `symbol` instead of `name`.
   - **Impact**: Potential for a developer to use `symbol` as the property name
   - **Mitigation**: The schema section is unambiguous and wins (properties table clearly says `name: String`), and D11 is clearly shorthand for "the symbol's name"
   - **Recommendation**: Would be clearer if D11 said `repo` + `file` + `name` + `kind` to exactly match the Cypher constraint. Not blocking because the authoritative schema section is correct.

### LOW — follow-up candidates

1. **APOC unrestricted unnecessary**: The K8s manifest spec includes `NEO4J_dbms_security_procedures_unrestricted: "apoc.*"` but no APOC procedures are used in any of the Cypher patterns. Neo4j Community 5.x includes APOC Core by default without needing this setting. The `unrestricted` flag is for APOC Extended which isn't installed. Harmless but unnecessary.

2. **scip-go install path**: The Dockerfile snippet installs Go 1.22 then removes it after building scip-go. If future stories need Go for other purposes, this removal would be a pain point. But for the stated scope (only scip-go needs it), the cleanup is correct.

3. **No liveness/readiness probes in Neo4j manifest spec**: The zoekt.yaml pattern includes probes but the Neo4j manifest section in the design doc doesn't specify them. Developer for #1513 will need to add appropriate probes (Neo4j has a built-in `/` health endpoint on HTTP port 7474).
