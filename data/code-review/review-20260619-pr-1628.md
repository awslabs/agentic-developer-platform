## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge

1. **`test_budget_usage_tracker.py` ruff format violation** — ruff format wants to break a multi-argument call across lines (`bridge_cost_to_usage_logs(mock_conn, "req-456", Decimal("0.05"), ...)` at line 437-438). This will cause CI to flag the format check. **Recommend fixing before merge.**

2. **`get_cost_by_correlation_id()` defined but unused** — `cost_service.py:68-99` is dead code. It's clearly prepped for chain-view cost enrichment (which the issue mentions), but no route calls it today. Acceptable as scaffolding but technically a YAGNI concern. Not a blocker.

3. **SQLAlchemy model `index=True` vs. migration partial index mismatch** — `usage.py:28` has `index=True` which implies a full index, but the migration creates a partial index (`WHERE agent_run_id IS NOT NULL`). If `alembic autogenerate` is ever run, it may try to create a redundant non-partial index. Low practical risk since this team uses raw-SQL migrations, but worth a note.

4. **Lambda bridge WHERE clause semantic change** — The original `WHERE request_id = %s AND cost_usd = 0` now becomes `WHERE request_id = %s AND (cost_usd = 0 OR chat_log_s3_key IS NULL)`. This means a retry Lambda invocation will now match rows that already have cost populated (if `chat_log_s3_key` is still null), which changes the behavior of `rowcount`. The `CASE WHEN cost_usd = 0 THEN %s ELSE cost_usd END` guard prevents cost clobbering, and `COALESCE(chat_log_s3_key, %s)` prevents key clobbering. The semantics are correct — this is the architect's recommended pattern (comment #6, 🟠 3.3). No issue.

### LOW — follow-up candidates

1. **Chain view cost enrichment** — The chain endpoints (`/me/agent-invocations/chain/...`) don't enrich with cost yet. `get_cost_by_correlation_id` is ready but unwired. Follow-up issue recommended.

2. **`cost_status` field** — Per architect review (🟡 4.3), the frontend infers pending/not-metered from `total_cost_usd == 0 && status == 'in_progress'`. A server-side `cost_status` enum would be cleaner but is not required for v1.

3. **Frontend `CostBadge` shows "pending" only for `status === 'in_progress'`** — A run that just completed but whose Lambda hasn't fired yet will show `$0.00` instead of "pending". The async lag (documented in Known Caveats) makes this acceptable for v1.

## Recommendation

**APPROVE** — pending the ruff format fix on `test_budget_usage_tracker.py` (1-line change, non-blocking if CI is acceptable with it as pre-existing).

All acceptance criteria from the issue and architect design are satisfied. The implementation is clean, follows established patterns (contextvar for hot-path data, `Depends` for header extraction, raw-SQL migration, COALESCE for idempotent Lambda UPDATEs), and includes comprehensive test coverage across all layers. Tenant isolation is maintained through the existing DynamoDB user/tenant-scoped activity query — cost enrichment only fetches for IDs the caller already has access to.
