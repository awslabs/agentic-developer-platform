## Findings (by confidence)

### MEDIUM — discuss before merge

1. **§2.2 Lazy extraction timing**: The doc recommends "fire on next-session-start if previous wasn't extracted." This adds latency to session start (the architect's own comment notes "if lazy extraction takes >5s, skip it"). The issue comment (Comment 6) recommends capping at 5s. This is a design choice that will need to be validated at implementation time. **Not a blocker** — the implementation issue (A) should specify the timeout.

2. **§2.7 New persona value `"chat"`**: The `Persona` enum currently has `developer`, `architect`, `reviewer`, `operations`. Adding `"chat"` means synthesis groups separately for chat-derived learnings. This is intentional per the design, but the open question (§7, Q2) acknowledges the alternative (inheriting agent persona). **Not a blocker** — flagged as an open question for stakeholder review.

### LOW — follow-up candidates

1. **§2.5 Phone regex over-broad**: The pattern `/\+?[\d\s\-()]{10,}/` will match many non-phone sequences (e.g., long formatted numbers in code). The doc acknowledges "over-redacts is fine" which is acceptable for a privacy-protecting design. Implementation should tune this.

2. **§7 Open questions**: 4 open questions listed for stakeholder review. These are appropriate for a design doc — they don't block the design itself, only the implementation.
