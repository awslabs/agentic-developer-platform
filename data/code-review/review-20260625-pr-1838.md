## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge (post-merge recommendations)

1. **query_cross_repo_impact Steps 2/3 unscoped** (neptune_client.py:801-845): The tenant scope filter is only applied to Step 1 (symbol resolution) but NOT to Step 3 (cross-repo caller discovery). This means callers from ANY tenant's nodes could appear in cross-repo results. This appears intentional (cross-repo queries are about discovering external callers regardless of tenant), but should be documented explicitly.

2. **Tenant filter not yet wired into request path**: `structural_backend.py` (the layer handling actual user requests) does not pass `tenant_id` to Neptune query functions. The feature is plumbing-only — repo-level ACL in `server.py` remains the sole enforcement mechanism. A follow-up issue should wire tenant_id from request context.

3. **`OR tenant_id IS NULL` semantics**: If an ingestion bug leaves a private node without tenant_id, it becomes visible to all tenants. This is a deliberate design decision (shared corpus nodes are NULL-scoped), but creates a surface for data leakage if ingestion fails mid-stream. Acceptable for current maturity level but should have monitoring.

4. **query_dir_symbols Cypher structure** (neptune_client.py:673): The scope is appended directly after `$dir_prefix` without `WHERE true` pattern used elsewhere:
   ```
   WHERE s.file STARTS WITH $dir_prefix{scope}
   ```
   This produces: `WHERE s.file STARTS WITH $dir_prefix AND (s.tenant_id = $tid OR s.tenant_id IS NULL)` — which is correct because `AND` binds tighter than `OR` in the parenthesized fragment. No issue, just a different pattern from other queries.

### LOW — follow-up candidates

1. **`node_var` f-string interpolation** (neptune_client.py:114): The node variable name is interpolated directly into Cypher. All current callers use hardcoded string literals, so no injection risk. A defensive `assert re.match(r'^[a-z_]\w*$', node_var)` would prevent future misuse.

2. **`updated_nodes: -1` in backfill return** (graph_ops.py:172): Neptune SET doesn't return affected count, so the backfill always returns -1. Consider using a separate COUNT query before/after for operational visibility.

3. **Test file uses `sys.path.insert`** (test_neptune_tenant_filter.py:953,1007,1064,1093,1121): The test modifies sys.path at runtime for imports. This is fragile but common in this codebase's test patterns. Not blocking.
