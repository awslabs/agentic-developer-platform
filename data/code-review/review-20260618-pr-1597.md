# Review of PR #1597

## Driving issue
- #1588: [Neptune EPIC #1529] Build per-repo × per-verb golden eval dataset (agent reads each GitHub repo to ground answers)

## Acceptance criteria checklist

The issue requires:

1. **[✗] Comprehensive golden-answer dataset (5 queries per applicable verb per repo)** — NOT delivered. The PR adds only a `coverage_manifest.yaml` (a metadata/manifest file). The **primary deliverable** — a new/extended golden dataset file (`golden_grounded.yaml` or equivalent) with ~200+ questions grounded in actual repo source — is entirely absent.

2. **[✗] Agent reads each GitHub repo to author grounded questions** — NOT delivered. No golden questions were authored from reading the repos. The existing `golden.yaml` (84 questions, 5 per repo across mixed verbs) pre-dates this issue and is not the grounded, comprehensive dataset required.

3. **[~] Per-repo coverage manifest (which verbs apply + why)** — PARTIALLY delivered. `coverage_manifest.yaml` exists and documents verb applicability per repo with rationale. However, it contains factual errors (see findings below).

4. **[✗] Anti-gaming: expected facts verifiable in source with file+line/symbol** — NOT delivered (no golden questions exist in this PR).

5. **[✗] Machine-scoreable by run_eval.py** — NOT applicable (no golden questions to score).

6. **[✓] remember/experience noted as round-trip test, NOT per-repo** — Correctly documented in the manifest's `non_repo_verbs` section.

## Findings (by confidence)

### HIGH — merge blockers

1. **Missing primary deliverable**: The entire golden-answer dataset is absent. The issue explicitly requires "5 probing queries + the correct answer derived directly from the repo source" per applicable verb per repo (~200+ questions). PR delivers 0 questions.

2. **Language hallucinations in coverage_manifest.yaml**:
   - `headroom`: Manifest says `[rust, python]`, but `corpus.yaml` (the source of truth) says `[javascript, typescript]`. The manifest was not grounded in actually reading the repo — it fabricated languages.
   - `CloakBrowser`: Manifest says `[python]`, but `corpus.yaml` says `[typescript, javascript]`. Another fabrication.
   - `last30days-skill`: Manifest says `[python, markdown]`, but `corpus.yaml` says `[javascript]`. Incorrect.
   - `Understand-Anything`: Manifest says `[typescript]`, but `corpus.yaml` says `[python]`. Incorrect.
   - `career-ops`: Manifest says `[javascript, markdown]`, but `corpus.yaml` says `[python, markdown]`. Incorrect.
   - `agent-skills`: Manifest says `[markdown, javascript]`, but `corpus.yaml` says `[markdown, typescript]`. Minor but still wrong.

   These errors indicate the manifest was authored from memory/hallucination rather than by reading the actual repos (violating the issue's core requirement: "Do NOT author questions from memory or the repo name — read the actual files").

3. **Neptune call graph claims are unverified**: The manifest asserts `neptune_call_graph: true` for 6 repos (headroom, Agent-Reach, CopilotKit, codegraph, Understand-Anything, CloakBrowser). The issue says "~9 repos have Neptune call graphs" but these assertions are not grounded in verifying the actual index state. Given the language errors, these claims are suspect.

### MEDIUM — discuss before merge

1. **CopilotKit included despite being excluded from corpus**: The manifest includes CopilotKit with a note "excluded from active corpus due to OOM on DeepWiki" but still sets all verbs to `true`. If it's excluded from the active corpus, golden questions targeting it will always fail. The manifest should mark it as `excluded: true` or set `applicable_verbs` to reflect what can actually be evaluated.

2. **No schema validation**: The manifest YAML has no reference in `run_eval.py` — the eval runner only loads `golden.yaml` and `corpus.yaml`. The manifest is useful documentation but isn't consumed by any tooling. This is fine as a first step, but means it won't be automatically validated.

### LOW — follow-up candidates

1. **Verb naming inconsistency**: The manifest uses `search_exact` and `search_semantic` as separate boolean fields, while the issue describes `search` as a single verb with diversity requirements ("mix exact-token and semantic/vocabulary-mismatch"). Minor structural choice.

2. **Missing `description` field**: Unlike `corpus.yaml`, the manifest doesn't include `description` per repo. Not required but would aid readability.

## Recommendation

**REQUEST CHANGES** — The PR delivers approximately 10% of the required work (only the coverage manifest, which itself contains factual errors). The primary deliverable — a comprehensive, repo-grounded golden eval dataset — is entirely missing. The developer agent appears to have timed out after producing only the manifest.

Specific actions needed:
1. Fix the language errors in `coverage_manifest.yaml` (align with `corpus.yaml` or verify against actual repos)
2. Produce the actual golden dataset (`golden_grounded.yaml`) with 5 questions × applicable verbs × repos
3. Ensure every question is grounded in real repo source with file+line/symbol references
4. Verify compatibility with `run_eval.py` format
