## Findings (by confidence)

### HIGH — merge blockers
None.

### MEDIUM — discuss before merge
- `modules/gateway/src/proxy/service.py`: The `_log_usage()` call doesn't pass `request_id` or `bedrock_account_id` (both optional params on `UsageService.log_request()`). The issue's design mentions `request_id=context.request_id` — but `TokenContext` has no `request_id` field. This is fine as-is (both params are optional/None), but a follow-up could add request correlation. NOT a blocker.
- Middleware placement: `RequestLoggingMiddleware` is added between `LoggingMiddleware` and enforcement middleware. The ordering is correct — it executes after `TokenContextMiddleware` sets `request.state.token_context` on the request path, and sees the final response status on the response path.

### LOW — follow-up candidates
- The issue's Piece 3 (org_id hygiene for legacy agents without org_id) is not addressed. Explicitly noted as optional in the issue — fine for follow-up.
- `invoke_stream()` does not write to `usage_logs`. This is consistent with existing behavior (stream metrics aren't emitted either) but could be a follow-up.

## Recommendation
APPROVE — all acceptance criteria satisfied, no security issues, no merge blockers.
