## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge

- **`tags` column type mismatch** (`platform/scripts/seed-shared-corpus.py:181`): The seed inserts `'[]'::jsonb` (JSON array) for the `tags` column, but:
  - Migration 020 defines `tags JSONB DEFAULT '{}'::jsonb` (JSON object)
  - Pydantic schema `AssetResponse.tags` declares `dict[str, Any]` (JSON object)
  
  This won't crash at INSERT time (Postgres accepts any JSON in a JSONB column), but when the gateway API reads these rows back, Pydantic will fail to deserialize `[]` as `dict[str, Any]`, potentially causing 500 errors on list/detail endpoints.

  **Suggested fix:** Change `'[]'::jsonb` to `'{}'::jsonb` to match the migration default and schema expectations.

- **`allowed_principals` not set in gateway DB** — The issue specifies `allowed_principals=['*']` but this column doesn't exist in the gateway-side `knowledge_assets` table (only in agent-context DB). The design intention is that the ingestion dispatch (SQS → agent-context worker) handles setting `allowed_principals` in the agent-context DB. This is architecturally correct but means the "shared visibility" contract depends on the ingestion pipeline correctly setting `['*']` — not directly enforced by this seed script. No code change needed, but the operational dependency should be noted.

### LOW — follow-up candidates

- **No rollback script included** — Issue #2089's Deployment section mentions "delete the 14 `registered_by='platform'` shared rows" as rollback, but no corresponding teardown script exists. Consider adding a `--teardown` flag or separate cleanup script for operational parity.
- **`autocommit=True` means each INSERT is its own transaction** — If the script fails mid-run (e.g., network issue after 7 inserts), a partial state results. This is safe due to idempotency (re-run completes the remainder), but wrapping all 14 in one transaction would provide atomicity. Low priority since idempotency makes partial state recoverable.
