### MEDIUM — discuss before merge

1. **Redundant `source _common.sh` in deploy.sh** (line ~177 of the diff): `_common.sh` is already sourced at line 108 and 120 of `deploy.sh`, so `template_file` is already available. The extra `source` is harmless (idempotent) but adds clutter. Not a blocker.

2. **Bonus fix: BEDROCK_REGION export in CI workflow** (line 217): The PR adds `BEDROCK_REGION` to the export list for the "Deploy DeepWiki" step. This is correct — `deepwiki.yaml` references `${BEDROCK_REGION}` at lines 47 and 49, and the old CI step didn't export it (it would have resolved to empty string, meaning the pod would have no `AWS_REGION` env var set). This is a good fix but goes slightly beyond the issue's stated scope. Not a blocker — it's a closely related pre-existing bug caught as part of the fix.

3. **Config drift risk**: The inline JSON in `deepwiki-configmap.yaml` is a copy of `images/deepwiki/config/{generator,embedder}.json`. Future edits to those source files won't automatically propagate to the manifest. A comment in the manifest noting the source would help. Low priority follow-up.
