## Findings (by confidence)

### HIGH — merge blockers

1. **Dockerfile: gh binary path collision (BREAKS ALL `gh` COMMANDS)**
   - `Dockerfile` line 123: `mv /tmp/gh_${GH_VERSION}_linux_amd64/bin/gh /usr/local/bin/gh`
   - `Dockerfile` line 183: `COPY ... gh-wrapper /usr/local/bin/gh` (overwrites real binary)
   - `gh-wrapper` line 9: `exec /usr/bin/gh "$@"` (this path does not exist)
   - **Impact**: ALL `gh` commands fail with "No such file or directory" on the new image. This breaks not just the long-running agents, but all agent personas immediately.
   - **Fix**: Move the real `gh` binary to `/usr/bin/gh` before the COPY, or install the wrapper at a different path and configure `PATH` ordering. The simplest fix is adding `RUN mv /usr/local/bin/gh /usr/bin/gh` before the COPY line.

### MEDIUM — discuss before merge

1. **Double `writeTokenFile()` on initial startup**: `agent-worker.ts` calls `getToken()` (which internally calls `writeTokenFile()` if it refreshes — and it will on first call since `currentToken` is null), then separately calls `writeTokenFile(initialToken)` again. This is harmless (same token, atomic write) but redundant. Consider removing the explicit `writeTokenFile(initialToken)` since `getToken()` already handles it on first call.

2. **No trailing newline in token file**: `writeFileSync(tmpPath, token, { mode: 0o600 })` writes the raw token string. `cat` in the shell scripts outputs this without a trailing newline. For `git-askpass-helper` this is fine (git trims), and for `gh-wrapper` the `$(...)` command substitution trims trailing newlines. Verified: this is safe. (Informational only.)

### LOW — follow-up candidates

1. **Token file not cleaned up on exit**: The token persists in `/tmp/.adp-gh-token` after the agent process exits. In a pod this doesn't matter (pod is ephemeral), but for local dev it leaves a credential on disk. Could add cleanup in the `process.on('exit')` handler. Not blocking.

2. **`gh auth status` behavior with wrapper**: The wrapper injects `GH_TOKEN` which makes `gh auth status` report "Logged in to github.com account (keyring)" or similar. If an agent ever checks auth status programmatically, the output may differ from expectations. Low risk since no code does this today.

## Recommendation
**REQUEST CHANGES** — HIGH finding #1 (gh binary path collision) is a critical regression that would break all agent personas on image rebuild. Must be fixed before merge.
