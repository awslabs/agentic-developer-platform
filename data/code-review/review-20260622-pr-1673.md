### LOW — follow-up candidates

1. **`InvocationListResponse` missing `count` field** — The flat view's `InvocationListResponse` doesn't include a `count` field in the TypeScript type (only `items` + `last_key`), but `ChainListResponse` has one. The unified `data` variable accessed for pagination (`data?.last_key`) works fine for both because `last_key` exists on both. The frontend handles both shapes correctly by splitting into `chainData`/`flatData` for type-specific access. No issue, just noting the asymmetry for future alignment.

2. **`desc.total_cost_usd` in frontend checked with `!= null`** — This works correctly (catches both `null` and `undefined`), but it's a slightly different pattern from the root's `ChainCostBadge` which checks `cost === null || cost === undefined`. Both are fine.

3. **Admin "by chain" toggle invisible** — When switching from `Mine` to `All (Admin)`, the "By chain" / "By run" toggle disappears (correct per spec), but `groupBy` state remains `'chain'` internally. This doesn't cause bugs because `isChainView = groupBy === 'chain' && viewMode === 'mine'` ensures chain queries only fire for `mine`. When switching back to `Mine`, the toggle reappears with the previous selection preserved, which is a nice UX. No action needed.
