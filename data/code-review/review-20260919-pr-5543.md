## New defect I found and repaired

**Evidence integrity — a state record named two files but pinned one.**
The `superplane_node_crs` existing-state record concatenated the SuperplaneNode
and NodePool references while publishing only the *first* file's sha256. The
nodepool listing behind an enumerated handle could be altered undetected —
contrary to U12-004's requirement that a record carry both evidence location and
hash.

Repair: `_Reference.combined()` (`live_observer.py`) derives one reference whose
digest is taken over each part's `reference:digest` line, so it changes if either
constituent read changes, with order fixed by argument order rather than dict
iteration. Regression
`test_a_multi_read_state_record_pins_every_file_it_names` asserts the published
digest is not any single retained file's digest and that mutating either part
changes it; **proven failing against the pre-fix code.**

## Security review

`/security-review` ran over the PR diff plus my repair, focused on subprocess
argv construction, bearer-token handling, `_safe()` sanitization, evidence and
raw-store write paths, JSON parsing, and whether the read-only claim can be
bypassed.

**No HIGH or MEDIUM findings.** Verified sound: fixed argv with `shell=False` and
DNS-label-validated namespaces (no command injection); exact-match read
allow-lists consulted before the URL is built, so `/launch` and `/down` are
unreachable and there is no mutating method; redirects refused rather than
followed, with urllib frames detached so headers cannot leak; `json.loads`
hardened against duplicate keys and `NaN`/`Infinity`, with no `pickle`, `eval`,
or `yaml.load`; evidence written via `os.link` (refuses existing files and
symlinks) at `0o600`, raw store `O_EXCL` at 0700/0600 with code-derived labels —
no traversal or overwrite. Command-injection payloads via namespace, non-`http(s)`
and credential-bearing URLs, and absent/CRLF tokens were all refused in my own
probes. No credential or response body reaches a published field.

Two defense-in-depth observations, deliberately **not** raised as findings
because both depend on operator-controlled environment variables and
supervisor-reviewed target metadata — trusted inputs under the review's own
exclusion rules:

1. `KubectlReads` validates that `SUPERPLANE_LIVE_KUBECONFIG` is a regular file
   but not its contents, so a kubeconfig `exec` credential plugin would run.
   `installation/runner.py:394-437` already implements the content allow-list
   that would close this; reusing it here would be worthwhile hardening.
2. `SkyPilotReads` permits `http://` and attaches the bearer token regardless of
   scheme. The documented in-cluster origin is plaintext.

Both are reasonable follow-ups for the supervisor to weigh **before a live run
with a real credential**, since that is the first moment either matters.
