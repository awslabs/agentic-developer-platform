### LOW — follow-up candidates

1. **Migration downgrade data loss warning**: The downgrade() function reverts to VARCHAR(512/128) with a comment "will fail if data exceeds limits" — this is appropriate since the fix is specifically about data that exceeds limits. The comment is sufficient documentation. No action needed.

2. **No new test for the warning log path**: The PR adds warning logging but doesn't add a test that exercises the >1024 char path. This is acceptable for a belt-and-suspenders log that doesn't affect behavior — the existing 17 unit tests cover the functional paths. If desired, a follow-up could add a test with a FakeNormalizedVuln having a 1025-char affected_versions string and asserting the log was called.

3. **Single-transaction ALTER**: The migration executes all 3 ALTER COLUMN statements in a single SQL string (one implicit transaction). This is correct for Postgres — ALTER TYPE on text columns is a metadata-only operation (no table rewrite) so it's fast and safe even on large tables.
