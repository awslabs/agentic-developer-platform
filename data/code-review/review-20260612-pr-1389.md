## Findings (by confidence)

### HIGH — merge blockers

None.

### MEDIUM — discuss before merge

1. **`ghcr.io/sourcegraph/zoekt:latest` tag** (`manifests/zoekt.yaml:55`): Using `:latest` in a K8s deployment is acceptable for dev (as the architect noted) but should be pinned to a digest before prod promotion. The architect's review (Comment 9) already flagged this as an "Important Issue" with the same recommendation. **Verdict**: not a blocker for dev, but should be tracked as a follow-up.

2. **Shard directory layout** (design doc section 3.1 shows nested `aws-e/adp/` directories): The architect's review (Comment 9, item 2) notes Zoekt's `shardWatcher` uses `os.ReadDir` (non-recursive). The design doc acknowledges this will be resolved in the indexing hook follow-up. The webserver's `-index /data/zoekt-shards` flag points at the mount where the Mountpoint CSI driver presents all S3 objects. Since the indexing hook is deferred, this is a design-time concern, not a code bug. **Verdict**: acceptable; tracked for indexing hook follow-up.

### LOW — follow-up candidates

1. **`urljoin` usage** (`zoekt.py:109`): `urljoin(self._base_url + "/", "api/search")` correctly handles trailing-slash normalization but is slightly indirect. A simpler `f"{self._base_url}/api/search"` would be equivalent given the `rstrip("/")` in `__init__`. Non-functional, purely aesthetic.

2. **Health check endpoint** (`zoekt.yaml:86-87`): Probes hit `/` which returns the Zoekt UI page. A `POST /api/search` with empty body would be more specific, but the root endpoint is sufficient for k8s liveness/readiness.

3. **Resource limits** (`zoekt.yaml:78-82`): Fixed `replicas: 1` with 4Gi memory limit. For 100+ repos the total shard size may exceed this. An HPA based on memory pressure would be prudent for scale — acceptable as a follow-up.
