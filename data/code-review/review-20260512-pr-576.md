## Findings (by confidence)

### HIGH — merge blockers

- `src/internal/auth_deps.py:39-41`: `ruff format` violation — multiline `HTTPException(...)` should be single line per project config. **Fixed by reviewer.**

### MEDIUM — discuss before merge

- `src/internal/routes.py:49`: `_verify_internal_key` remains as dead code (no longer imported by any route). Not harmful during the dual-auth window, but worth noting for the follow-up cleanup PR. NOT a merge blocker.

- `modules/agent-factory/infra/agent-registry-seed.tf:29`: `hash_key = "agent_id"` — this assumes the agent_registry DynamoDB table uses `agent_id` as its partition key. If the table uses a different key name (e.g., `PK` or `role_arn`), the Terraform apply will fail. The issue says "agent_id" is correct based on `get_agent_by_role_arn` using a GSI, but the reviewer cannot verify without seeing the table definition. Low risk since this is a separate `terraform apply` step (failure is visible before deploy).

### LOW — follow-up candidates

- `test_auth_deps.py:103`: `assert resp.status_code in (403, 500)` is a loose assertion for the unregistered-agent test. Ideally should be exactly 403. Works because the `BedrockGatewayError` conversion handles it, but the loose assertion could mask a regression. Consider tightening in a follow-up.
- Worker client uses `botocore.auth.SigV4Auth` (internal API) — acceptable per architect's review (Comment 6, Nice-to-have #6) since botocore is always available alongside boto3.
