## Findings (by confidence)

### HIGH — merge blockers (FIXED by reviewer)

1. **cyber-worker-build.yml:118** — `steps.build.outputs.registry` is empty (composite action outputs only `build_id` and `source_key`). Should be `steps.build_info.outputs.registry`. Docker login with empty registry string silently fails (`|| true`), but subsequent `docker run` to extract manifest would fail because the runner isn't authenticated to ECR.
   - **FIXED**: Changed to `steps.build_info.outputs.registry`

2. **cyber-worker-build.yml:141** — SSM parameter update uses `steps.build.outputs.image_tag` (empty). Would write empty string to `/adp/dev/cyber/worker-image-tag`, breaking downstream consumers that use this to identify the deployed image.
   - **FIXED**: Changed to `steps.build_info.outputs.image_tag`

3. **cyber-worker-build.yml:153,155** — Summary step uses `steps.build.outputs.registry/image_tag` (empty). Cosmetic but confusing.
   - **FIXED**: Changed to `steps.build_info.outputs.*`

4. **chat-agent-deploy.yml:174** — Summary step uses `steps.build.outputs.registry/image_tag` (empty). Cosmetic but confusing.
   - **FIXED**: Changed to `steps.build_info.outputs.*`

### MEDIUM — discuss before merge
- None remaining after fixes.

### LOW — follow-up candidates
1. `deploy-all.sh` passes `BUILDSPEC_FILE` parameter to `run_codebuild` which is declared "unused" — minor dead code. Not a bug, just noise.
2. The `agent-context` TF module (`images-build/main.tf:98`) still has `location = "${var.state_bucket}/codebuild/adp-source.zip"` as the project default — this is intentional per the approved design (override always wins), but should be noted for future cleanup.
3. The `eval "VARS_ARRAY=(${ENV_VARS})"` in the composite action is a shell injection risk if a caller passes untrusted content as `environment_variables`. In this repo all callers are controlled workflows with hardcoded values, so it's low risk, but a follow-up could use IFS-splitting instead of eval.
