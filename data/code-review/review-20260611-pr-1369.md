## Findings (by confidence)

### HIGH — merge blockers

1. **`agent_learning/2026-06-11-issue-1359-learnings.md`**: This file is committed despite `agent_learning/` being listed in `.gitignore` (line 63: "Agent-generated per-issue learnings dumps — do not commit to repo"). This violates the repo's "must not commit" rules. The file must be removed from the PR.

### MEDIUM — discuss before merge

1. **Duplicate design docs**: Both `docs/design-1359-vuln-matching-engine.md` (221 lines) and `docs/vulnerability-matching-engine-design.md` (390 lines) cover substantially the same content. The first is a review note; the second is the implementation-ready design. Having both creates maintenance burden and confusion about which is authoritative. Recommend keeping only one (the more detailed `vulnerability-matching-engine-design.md`) and removing or converting the other to a link.

2. **Duplicate normalization logic**: `codebuild/normalize-vuln-findings.py` (standalone, 281 lines) duplicates logic from `modules/agent-context/pipeline/vuln_scanner/normalize.py` (package, 299 lines). The PR notes at agent_learning line 96: "keep them in sync" — but code duplication always drifts. This is acceptable for now (CodeBuild doesn't install the agent-context package) but should get a follow-up to DRY this up (shared module or pip install the package in CodeBuild).

3. **`_extract_cvss_score` in normalize.py has a dead `pass` branch** (line ~73-76): The CVSS vector string detection (`if score_str.startswith("CVSS:")`) does nothing (just `pass`). This means CVSS vector strings like `"CVSS:3.1/AV:N/AC:L/..."` will fall through to `float()` conversion and raise ValueError, getting silently swallowed. This is technically handled (returns None) but means CVSS scores expressed as vectors (common in OSV data) will never be extracted. Not a blocker since the test fixtures use numeric strings, but real-world OSV data often uses vector format.

### LOW — follow-up candidates

1. **No tests for `scanner.py`**: The scanner orchestration module (subprocess calls) has no tests. This is expected for now (needs mocking of subprocess calls) but should be tracked.

2. **`codebuild/normalize-vuln-findings.py` has no tests**: The standalone normalizer isn't tested by the existing test suite. It should be covered by integration tests when the full pipeline is wired.

3. **Re-scan cron not implemented**: The design docs discuss daily/weekly re-scan but no implementation is provided. This is correctly scoped as future work.
